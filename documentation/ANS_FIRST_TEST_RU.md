# Первый тест Apple ANS: ANS001

Статус: offline-комплект для первого ANS001 готов и прошёл проверку команды
запуска без обращения к устройствам. Разрешение на MacBook Air не получено;
аппаратный тест не выполнялся. Полный V1 DMA и загрузка установленной Windows
через AppleAns не готовы — ниже указана точная граница этого комплекта.

Комплект: `.local/ans-native/ANS001-ready/` в отдельном ANS worktree.
Манифест `qualification.json`, SHA-256:
`466036d0f86d9e3a6adff573b25ce1253bf1907811910f95c952f7bf777aecaf`.
Файлы пакета сделаны read-only. `COMMANDS.json` содержит отдельно проверенную
команду dry-run и будущую команду, требующую разрешения пользователя.

## Что будет загружаться

Отдельный Windows PE ARM64 из предварительно загруженного RAM-диска. Файлы
WinPE и его системный диск X: не зависят от нового драйвера внутреннего SSD.
Пакет AppleAns в ANS001 отсутствует. Установленная Windows с C: через AppleAns
в этом тесте не загружается.

Прошивка до ExitBootServices использует существующий путь хранения. При
передаче управления Windows проверяется прекращение новых recovery-запросов,
завершение старых, реальный Flush, остановка контроллера/RTKit и скрытие
виртуального PCI NVMe. После передачи управления Windows должна видеть
ACPI\APPL0003 без привязанного драйвера. Внутренний SSD на этой стадии
недоступен; это ожидаемый результат, а не ошибка установки драйвера.

Тест меняет состояние контроллера: его нельзя называть запуском без доступа
к ANS. Он не предназначен для создания разделов, форматирования или проверки
записи. Наличие отдельного WinPE не является гарантией исправности нового
механизма передачи управления — именно это и проверяется.

## Порядок после готовности комплекта и разрешения

1. Согласовать отдельное время, когда GPU-эксперимент не выполняется. Сначала
   проверить доступность обычной Windows и состояние существующего launcher,
   proxy и vUART. Запущенную GPU-сессию самостоятельно не прерывать.
2. Зафиксировать ANS001 в журнале: точные версии, SHA-256 всех образов, профиль,
   единственное изменение, ожидаемые признаки, лимит ожидания и восстановление.
3. Проверить локальные хеши m1n1, Mu, RAM-диска WinPE и recovery. Предварительная
   проверка должна завершиться до первого обращения к Air. Промежуточные
   файлы из каталогов сборки напрямую не запускать.
4. Загрузить только утверждённый комплект ANS001. Native-профиль Mu допускает
   Windows boot manager только с указанного RAM-диска; внутреннего fallback нет.
5. Сохранить host/vUART журнал загрузки и запуска, признаки загрузки WinPE,
   список ACPI/PCI/дисковых устройств и сведения о пакетах/драйверах. Проверить
   APPL0003, отсутствие виртуального NVMe и отсутствие AppleAns.
6. Сначала сохранить результаты, затем вернуть согласованную конфигурацию,
   которая была рабочей непосредственно перед ANS001.
   Не повторять неудачный запуск автоматически и не переиспользовать состояние
   при неопределённом завершении DMA. Для такого отказа нужен отдельный
   предусмотренный путь восстановления с новым состоянием контроллера.

Работа GPU может продвинуться до первого ANS-теста. Поэтому сохранённые сейчас
старые recovery-образы не считаются автоматически правильным откатом для
будущего установленного GPU-драйвера. Перед тестом фиксируются актуальная
совместимая пара m1n1/Mu и состояние пакета GPU; обычный возврат должен вернуть
именно эту конфигурацию. ANS001 не удаляет и не переустанавливает GPU-пакеты на
внутренней Windows. Старые неизменяемые образы остаются отдельным аварийным
средством, с явно согласованным порядком восстановления.

Точные аргументы записаны в `ANS001-ready/COMMANDS.json`. Команда dry-run уже
завершилась с кодом 0 и не обнаруживала порты, не запускала chainload и не
открывала UART. Аппаратный вариант отличается явным `--confirm-experiment
ANS001` вместо `--dry-run`; его нельзя запускать до согласования окна, проверки
обоих каналов управления и подходящего восстановления.

Host-логи запуска создаются только в ANS worktree: `hv.log`, `guest-uart.log`,
`guest-uart.tlog`, `guest-uart-reader.log`. Отдельная квитанция launch contract:
`.local/ans-native/ANS001-run/launch-contract.bin`. WinPE пишет только в
`X:\ANS001-RESULTS`; до перезагрузки эти RAM-логи нужно сохранить на заранее
идентифицированный внешний носитель. Номер диска, том и букву нельзя угадывать.
Флешка нужна для логов, не для загрузки: WinPE предзагружается с хоста в RAM.
Ввод WinPE и возможность подключить носитель должны быть доступны для теста.

Сырая MMIO-квитанция handoff не экспортируется текущим сборщиком. Успешный
переход к WinPE при точно проверенном native Mu означает, что обязательный EBS
проверяющий код принял квитанцию. Это вывод из проверенного пути исполнения;
Сырой дамп квитанции при этом не сохраняется.

## Критерии ANS001

Успех: WinPE достиг рабочего состояния через обязательный native EBS gate; APPL0003 присутствует без AppleAns; виртуальный PCI NVMe отсутствует;
внутренний диск не открыт; журналы сохранены и recovery восстановлен.

Неуспех: зависание или отказ передачи владения, неожиданная загрузка внутренней
Windows, наличие старого виртуального NVMe после handoff, непредусмотренная
привязка AppleAns либо невозможность получить необходимые свидетельства.
Одна только картинка WinPE без проверки точного образа и списка устройств успех не доказывает.

## Текущая граница готовности драйвера

В комплекте ANS001 гостевой DMA остаётся запрещённым. Реальный assisted-контракт
помечает области таблиц DART как UNOBSERVED; считать такую область пустой нельзя.
Передача владения после доказанной остановки recovery отделена от допуска DMA,
поэтому перечисление устройства без драйвера можно проверить самостоятельно.
Состояние handoff READY означает завершённую передачу владения; оно не доказывает
запуск контроллера или административной очереди.

Код и пакеты последующих профилей собраны, но ANS003, Identify и READ пока не
допущены. Для них требуется полная доказуемая модель резервирования приватной
памяти DART, включая унаследованные таблицы и последующих владельцев. Текущий
код при неполном доказательстве отказывает до native boot и до DMA. Разрешение
на ANS001 не означает разрешения запускать эти следующие этапы.

## Следующие отдельные тесты

| Этап | Что проверяется | Зависит ли загрузка WinPE от AppleAns |
| --- | --- | --- |
| ANS001 | Передача владения, устройство без драйвера | Нет |
| ANS002 | QUERY/CLAIM, остановка до запуска контроллера | Нет |
| ANS003 | Административная очередь, остановка до Identify | Нет |
| ANS004 | Identify контроллера и namespace | Нет |
| Чтение | Прямой READ, сравнение данных, нагрузка | Нет |
| Запись | Отдельный тестовый раздел, WRITE/Flush/восстановление | Нет |
| Native boot | Загрузка установленной Windows через AppleAns | Да |

Первые четыре этапа не подтверждают работоспособность чтения, записи или
загрузки C:. Каждый следующий запуск разрешается по результату предыдущего,
с отдельной гипотезой и точным пакетом. Обещать загрузку установленной Windows
до этих проверок нельзя.

## Завершённые offline-проверки

- Полный m1n1: чистый commit `2d869eb`, Mach-O и raw link успешны.
- Полный Mu: native и recovery FD, проверены 97 PE/COFF модулей каждого;
  native gate/AutoBoot и фактические AML/FFS соответствуют профилю.
- Пять ARM64 AppleAns-пакетов: WDK 26100, Code Analysis, InfVerif, каталог,
  тестовая подпись. Все 20 проверок Authenticode/членства прошли с тестовым
  корнем в одноразовой VM. Проверка Microsoft production kernel policy не
  пройдена; эти пакеты не включены в загрузочный WinPE ANS001.
- 96 Python-проверок, наборы ANS/Windows/Mu с ASan/UBSan и семь проверок
  гипервизора. Квитанции сохраняются по хешу, без перезаписи старых результатов.
- WinPE D: оба WIM-индекса и SAN3 проверены структурно; реальный сборщик
  отработал в программной VM, обязательные проверки и экспорт 73 RAM-файлов
  прошли. Дополнительные sc/DISM/WMIC недоступны; их реальные ошибки сохранены,
  утверждения об успехе всех команд нет.
- Независимое ревью пакета не нашло блокирующей ошибки в пределах ANS001.

Общий старый CHANGES.csv содержит 10 исторических неподдерживаемых change_type;
это не исправлялось переписыванием GPU-результатов. Строки ANS проверены отдельно
существующей схемой. Начальная изменяемая тестовая квитанция была перезаписана
старыми запусками; это отмечено явно, исходный записанный хеш не восстановлен
догадкой. Новые квитанции и ссылки неизменяемы.
