# J313 AGX G2 Opt-In ACPI Profile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce an opt-in J313 G2 firmware profile that enumerates `APPL0002`
with one exact SGX aperture and nine reviewed guest interrupts while leaving the
stable firmware and Windows Driver Store unchanged.

**Architecture:** Extend the existing immutable G2 JSON generator so ASL and
m1n1 policy are generated from the same source as the Windows header. Package a
separate SSDT only when the EDK II macro `J313_AGX_G2_PROFILE=TRUE` is selected.
Validate generated bytes, AML contents, and launch policy on the host before a
separately preregistered enumeration-only hardware boot.

**Tech Stack:** Python 3 `unittest`, EDK II DSC/FDF and ASL, ACPICA `iasl`, C11,
m1n1 launch-contract tests, Windows ARM64 WDK resource parser tests.

**Spec:** `documentation/design/2026-08-26-j313-agx-g2-acpi-profile.md`

## Global Constraints

- Work only on `feature/j313-gpu-acceleration` in `/Users/pavel/public_windows`.
- Do not modify or install the immutable stable recovery image.
- Do not install `AppleAgx.sys` during Task 4.
- Generate every address, GSIV, version, and hash from
  `config/j313-agx-g2.json`; do not duplicate literals manually.
- The stable DSC/FDF path must omit the AGX SSDT.
- The G2 profile contains one SGX MMIO descriptor and guest GSIVs `880..888`.
- No AGX clock, firmware, MMIO write, UAT mapping, or synthetic completion is
  permitted.
- A hardware boot requires a new preregistered experiment and fresh evidence
  directory after all host gates pass.
