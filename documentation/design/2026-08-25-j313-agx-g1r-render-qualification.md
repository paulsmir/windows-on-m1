# J313 AGX G1R Private Render Qualification

## Status

Approved on 2026-08-25 as the replacement for the rejected G1Q
barrier-only workload. G1R is an assisted, pre-Windows diagnostic gate. It
does not modify the stable Windows boot path, expose a display adapter, or
permit a host process to submit work after Windows starts.

## Evidence that requires the redesign

EXP-079 and EXP-081 proved that the G1Q transport was working through ring
entry fetch:

- context 63 and its UAT roots were accepted;
- the Submit3D channel message was consumed;
- firmware advanced the queue read pointers from 0 to 1;
- `GPU_DONEPTR` remained 0 and no completion event arrived;
- the canary, guards, firmware fault state, and sampled SGX IRQ state remained
  clean.

The pinned m1n1 ABI describes `WorkCommandBarrier.event` as the event that
triggers a stamp check. Every working `GPURenderer` path places the barrier
after a TA producer and before a real `WorkCommand3D`. There is no upstream
barrier-only submission. An already-equal stamp therefore does not turn the
barrier into an independently schedulable no-op. G1Q tested an invalid
workload assumption, not a broken command transport.

G1R replaces only that workload. The failed G1Q implementation and evidence
remain as a regression record and must not be repurposed by increasing its
timeout or changing its queue index.

## Goal and non-goals

G1R proves that the pinned J313/G13/V13_5 firmware and m1n1 structures can:

1. execute one complete TA-to-3D job in an isolated UAT context;
2. retire both queues and report their expected firmware events;
3. write a deterministic value to a private render target; and
4. release all diagnostic ownership before a mandatory reboot.

G1R does not prove WDDM ownership, guest interrupt delivery, paging, shaders
compiled inside Windows, presentation, TDR recovery, or production graphics
performance. Those remain later Windows-driver gates.

## Chosen workload

The gate replays one reviewed 16 by 16 RGBA8 clear generated by the pinned
Asahi Mesa userspace through the existing m1n1 DRM shim. The clear has:

- one color attachment;
- no depth or stencil attachment;
- no textures, vertex buffers, guest buffers, display addresses, or external
  resources;
- a fixed clear color and fixed dimensions;
- a fixed raw attachment SHA-256 after successful execution.

The capture is a complete m1n1 `GPUFrame`: its command buffer and every GPU
object required by the TA and 3D commands are present. Replay uses the pinned
`GPUFrame` and `GPURenderer` implementations because those are the known-valid
producer, barrier, real 3D command, microsequence, stamp, and event sequence
for this firmware version. G1R does not copy or partially reconstruct those
undocumented structures.

## Capture provenance

No anonymous or downloaded binary capture is accepted. The repository owns a
small capture program that performs only the fixed clear. A capture operator:

1. verifies the exact Mesa source commit, m1n1 source commit, J313 identity,
   G13/V13_5 contract, and sole proxy ownership;
2. runs the program through m1n1's DRM shim with frame dumping and attachment
   pull enabled;
3. captures the same clear twice from separate cold boots;
4. rejects either capture unless their normalized manifests, member hashes,
   command buffer, object inventory, and final attachment hash are identical;
5. packages one canonical ZIP plus a hash-bound JSON manifest; and
6. records the acquisition experiment and both cold-boot receipts.

Normalization removes ZIP timestamps and ordering differences but never edits
command or object bytes. A capture that contains uninitialized or
non-deterministic bytes is rejected rather than masked.

The canonical fixture and manifest are versioned together. The manifest binds:

- board, chip generation, firmware version, and ADT identity;
- Mesa and m1n1 commits;
- capture program SHA-256;
- complete ZIP-member names, sizes, and SHA-256 values;
- parsed command-buffer fields;
- exact GPU virtual-address intervals and map flags for every object;
- the sole attachment address, size, format, dimensions, and expected final
  raw SHA-256; and
- the canonical fixture SHA-256.

Any fixture or manifest change creates a new gate version and experiment.

### Historical capture bridge and reproducible host

The capture path is pinned to the historical Asahi Mesa bridge that actually
implemented m1n1 forwarding, not to the later no-op demonstration shim:

- repository: `https://gitlab.freedesktop.org/asahilina/mesa.git`;
- commit: `7a4f24061fa56ef7eff12132dd7b1461d5a890d8`;
- bridge source: `src/asahi/drm-shim/asahi_m1n1.c`;
- runtime artifact: `libasahi_m1n1_drm_shim.so`.

The bridge is a Linux-only `LD_PRELOAD` library. It embeds CPython, imports
`m1n1.agx.shim`, constructs `Shim(shim_device.mem_fd)`, and forwards the Asahi
DRM ioctls into the pinned m1n1 proxy API. It is not an executable launcher and
does not need to be tracked in the Mesa source tree. The acquisition operator
therefore requires all of the following independently:

- the exact clean Mesa source commit above;
- an ELF shim library located under that checkout;
- the exact SHA-256 of that built library supplied at preflight; and
- the exact pinned m1n1 ioctl ABI and capture-program SHA-256.

The host build is reproducible in an ARM64 Linux container based on
`ubuntu:22.04@sha256:2edbbc5dc405e9612ba3584ce95480277e3eb374407b5505fe26f17df77c7dbc`.
It builds the exact Mesa commit with only the Asahi Gallium driver, DRM shim,
EGL, GBM, GLES, and shared glapi required for the fixed clear. The exported
bundle contains the shim, `asahi_dri.so`, EGL/GLES libraries, fixed-clear
producer, verifier, and a hash manifest. Two independent no-cache builds must
produce byte-identical manifests before hardware is eligible.

The container receives the repository read-only and a separate evidence
directory read-write. A reconnecting host `socat` bridge exposes the physical
USB proxy as a container PTY without granting the container direct host-device
ownership. The bridge was independently loopback-tested in both directions.
A PTY path is never treated as sufficient readiness: the bridge opens its
TCP/USB side without `wait-slave`, preserves the PTY across individual client
processes, and observes a fixed settle boundary before m1n1's 150 ms bootstrap
NOP. A transport-only gate must prove J313/V13_5 identities and a changed m1n1
base across one mandatory reboot before a failed bridge may be used for another
GPU acquisition experiment.
A negative control using the exact EGL/GLES and Asahi override without the shim
must fail with `EGL_NOT_INITIALIZED`; it must never fall back to software
rendering or create an output artifact.

## Fixture validation

Fixture validation is pure and runs before hardware access. It fails closed on
any of the following:

- ZIP path traversal, duplicate member, unlisted member, compression bomb, or
  malformed JSON;
- a hash, size, address, map flag, contract identity, or source commit that
  differs from the manifest;
- overlapping frame objects, an object outside the reviewed private GPU VA
  ranges, or a missing command-buffer pointer target;
- any guest physical address, framebuffer interval, DCP scanout interval, or
  stable-boot allocation in the declared object inventory;
- more than one attachment, a depth/stencil attachment, dimensions other than
  16 by 16, or a color allocation outside the declared output object; or
- an expected output hash equal to the pre-submit poison hash.

The manifest is an allowlist, not descriptive metadata. Replay receives only
the validated immutable bytes and parsed values.

## Replay lifecycle

One G1R replay cycle runs only at `Running proxy...`, before guest entry:

1. Validate the immutable stable recovery manifest, exact J313 AGX contract,
   source commits, canonical fixture, and empty evidence directory.
2. Require sole proxy ownership and record a fresh randomized m1n1 identity.
3. Start the already-qualified G1 firmware lifecycle and require its heartbeat.
4. Create `GPUContext`, bind only context ID 63, account for its fixed
   `thing` mapping, and load the validated frame objects at their captured GPU
   virtual addresses.
5. Poison the sole private output attachment with the manifest's fixed
   pre-submit pattern and hash it.
6. Create `GPURenderer` with queue index 1, submit exactly one frame, and run
   both 3D and TA queues in the order used by the pinned renderer.
7. Service firmware messages only until both allocated completion events fire
   or the fixed 500 ms workload deadline expires. Polling observes evidence;
   it cannot manufacture completion.
8. Require exact TA and 3D stamp progress, exact queue producer/read/done
   progress, one matching event for each queue, no spurious or duplicate event,
   and the expected final output hash.
9. Snapshot firmware faults, readable physical faults, SGX IRQ state, channel
   pointers, queue state, events, stamps, UAT mappings, object hashes, output
   hashes, elapsed time, and cleanup state. The mapping inventory classifies
   every range as context bootstrap, frame object, renderer-owned allocation,
   or firmware-shared allocation; anything outside those reviewed allocators
   is undeclared.
10. Free renderer and frame objects, clear both context-63 roots under the UAT
    handoff lock, flush and invalidate, stop firmware management, and verify no
    diagnostic root or mapping remains.
11. Save the receipt atomically and physically reboot regardless of pass or
    failure. Never launch Windows from a failed or incomplete cycle.

The 500 ms limit starts immediately before submission, after firmware startup
and fixture loading. It is a versioned constant and cannot be tuned from the
command line.

## Completion contract

A replay passes only when all independent observations agree:

- exactly one TA work item and one 3D work item were submitted;
- both queue read and done pointers reach their expected producer positions;
- the TA and 3D completion stamps each make their exact expected transition;
- exactly one matching TA event and one matching 3D event are observed;
- the poisoned output changes to the manifest's known final SHA-256;
- every non-output immutable object retains its declared hash;
- the deadline is not exceeded;
- firmware and readable physical fault state are zero;
- no guard, mapping outside the reviewed context/frame/renderer allocators,
  unexpected interrupt, cleanup error, or root leak is present.

An event without output, output without both events, pointer-only progress,
duplicate events, or a correct-looking output after a deadline all fail.

## Isolation and safety

G1R owns only context 63 and its private allocations. It never maps context
zero guest memory, Windows RAM, DCP framebuffer memory, the physical scanout
buffer, or NVMe buffers. The diagnostic framebuffer and web display remain off.

Capture and replay are assisted-only destructive GPU experiments. Every live
run is preregistered with exact commits, hashes, command, deadline, evidence
directory, pass criteria, and stop rules. Hardware is rebooted after every run.
The stable recovery directory remains byte-identical and is the rollback point.

## Components

- `tools/agx_frame_fixture.py`: pure canonical fixture packaging, manifest
  generation, and strict validation.
- `tools/agx_render_gate.py`: pure replay receipt validation, lifecycle,
  immutable evidence, cold-cycle aggregation, and verification CLI.
- `tools/agx_m1n1_render_backend.py`: sole live hardware adapter; composes the
  proven G1 backend and pinned `GPUFrame`/`GPURenderer` implementation.
- `scripts/capture-agx-clear-frame.sh`: provenance-checked, assisted-only
  two-cold-boot fixture acquisition operator.
- `scripts/build-agx-capture-env.sh`: reproducible ARM64 Linux capture
  environment builder and atomic exporter.
- `scripts/run-agx-capture-container.sh`: read-only container runner and
  reconnecting host USB-proxy bridge.
- `scripts/probe-agx-capture-transport.sh`: transport-only cold-reboot gate;
  never imports or starts AGX.
- `tools/verify-agx-capture-env.py`: exact exported-artifact and manifest
  verifier.
- `tools/agx-capture-container/`: pinned build and runtime definitions.
- `scripts/run-agx-render-gate.sh`: provenance-checked one-shot replay and
  eventual ten-cycle cold qualification operator.
- `fixtures/agx/j313-g13-v13_5-clear-16x16/`: canonical capture, manifest, and
  human-readable provenance after the acquisition experiment passes.

Hardware access is excluded from imports so pure host tests do not require a
proxy or AGX modules. Normal assisted launch, standalone launch, Mu, ACPI,
Windows, and stable firmware files are outside this component boundary.

## Verification sequence

Production behavior is introduced test-first and observed RED before GREEN:

1. fixture parser and manifest mutation tests;
2. capture reproducibility and canonicalization tests using synthetic ZIP
   fixtures only;
3. strict replay receipt and lifecycle tests;
4. live adapter tests against complete deterministic fakes;
5. operator provenance, sole-owner, immutable-artifact, timeout, cleanup, and
   launch-isolation tests;
6. preregistered two-cold-boot fixture acquisition;
7. one preregistered hardware replay with mandatory reboot;
8. only after the one-shot result passes, ten cold-reset-separated cycles
   under reserved final experiment EXP-080; and
9. unchanged stable Windows boot verification after the final aggregate passes.

No hardware run is retried in place. A failure is analyzed and a newly
preregistered experiment receives a fresh evidence directory.

## Transition to the Windows driver

Passing G1R proves a complete private render submission using the pinned
firmware ABI. G2 then starts from the immutable stable Windows baseline and
implements direct Windows ownership:

- the ARM64 WDDM KMD owns power, firmware, UAT contexts, queues, interrupts,
  fences, faults, timeout detection, and reset;
- a UMD or tightly bounded bring-up command source supplies the same minimal
  render semantics without USB, Python, or EL2 submission;
- the last command writes a monotonically increasing progress fence;
- completion reaches Dxgkrnl through the KMD interrupt/DPC path; and
- TDR, invalid submissions, teardown, and repeated reboot are qualified before
  general shader or presentation support.

The capture is a diagnostic oracle only. It must not become the production UMD
or a permanent command replay mechanism.

## Rejected alternatives

### Keep the barrier-only gate

EXP-081 disproved its scheduling premise. A longer timeout or another queue
index cannot create the missing TA producer or following 3D work.

### Copy `agx_1tri.py`

That experiment depends on missing external `gpudata`, many fixed opaque
buffers, and a broad manually reconstructed command stream. It cannot provide
reviewable provenance or a minimal failure boundary.

### Invent a command stream from register guesses

The firmware ABI is versioned and only partially documented. A guessed stream
can hang the GPU or silently touch an unsafe address. The known-working pinned
renderer is the narrower and safer source.

### Download an arbitrary frame capture

Its source, firmware contract, uninitialized bytes, and address ownership
cannot be proven. Only a reproducible local capture from the pinned source is
accepted.

### Start with WDDM before private replay passes

That combines PnP, Dxgkrnl DDIs, memory management, firmware ownership,
submission, interrupt delivery, fences, reset, and TDR in one failure surface.
G1R isolates the firmware execution boundary first without changing Windows.

## Primary implementation references

- pinned m1n1 `m1n1.agx.render.GPUFrame` and `GPURenderer`;
- pinned m1n1 `m1n1.agx.shim.DRMAsahiShim`;
- pinned m1n1 AGX context, UAT, TA/3D queue, event, stamp, microsequence, and
  fault structures;
- Asahi Mesa's AGX command generation corresponding to the pinned capture
  commit;
- Microsoft WDDM command-buffer, progress-fence, interrupt, and TDR contracts.
