# EXP507 first failing SubmitCommand discriminator

## Boundary and hypothesis

EXP506 reached `DxgkDdiSubmitCommand` and returned `STATUS_INVALID_PARAMETER`,
which dxgkrnl reported as bugcheck `0x119/2`.  No submitted scalar receipt
survived, so the exact route and guard remain unknown.

WHY THIS HYPOTHESIS:

1. Event 41 record 18293 identifies the failed DDI as SubmitCommand and carries
   `STATUS_INVALID_PARAMETER`; the EXP506 host log independently reaches the
   physical DCP latch immediately before reset.
2. The current dispatcher can return the same status by routing an unrecognised
   private BLT to the render path, while `AdmissionPresentSubmit` has several
   independent exact-argument guards with the same status.
3. EXP506 persisted no Present/PresentTransfer receipt, so neither source review
   nor the existing ETL selects one guard.  Relaxing a guard would be guessing.

Single variable: add a qualification-only, crash-durable scalar trace of the
first non-paging SubmitCommand.  Do not change routing, validation, queueing,
completion, capabilities, firmware, memory, scanout or m1n1 behavior.

## Primary contracts inspected

- Pinned WDK 10.0.26100 `d3dkmddi.h`: exact
  `DXGK_SUBMITCOMMANDFLAGS`, `DXGKARG_SUBMITCOMMAND`, and DISPATCH_LEVEL DDI.
- Microsoft `DXGKDDI_SUBMITCOMMAND`: any error return causes `0x119/2`; parameter
  3 is the `DXGKARG_SUBMITCOMMAND` pointer.
- Microsoft `DXGK_SUBMITCOMMANDFLAGS`: a buffer generated by Present carries the
  Present bit; Reserved must remain zero.
- Microsoft `WRITE_REGISTER_ULONG` and `WRITE_REGISTER_ULONG64`: any IRQL is
  supported when the register is resident mapped device memory.
- Current m1n1 `hv_agx_power_broker.c` / `hv_agx_power_mmio.c`: QUERY accepts a
  strictly increasing request sequence, performs no power transition, and prints
  the accepted receipt sequence to the durable host log.
- Current render-admission `paging_windows.c`, `present_windows.c`,
  `submission_windows.c`, `work_queue_windows.c`, and existing EXP506 receipts.

## Contracts

WINDOWS CONTRACT:

`DxgkDdiSubmitCommand` is nonpageable and runs at DISPATCH_LEVEL.  All captured
data must be scalar and copied during the call; no pointer may be retained.
Returning an error immediately bugchecks Windows, so PASSIVE registry persistence
cannot be the only receipt path.

AGX/ASAHI CONTRACT:

No AGX firmware, queue, UAT, MMIO ownership, TA/3D, IRQ or completion contract is
changed.  This experiment observes the Windows-facing boundary before execution.

TRANSLATION:

Reuse the already hardware-proven mapped power broker and its QUERY command.  A
trace word is `0x5070_0000_0000_0000 | field_id << 32 | value`.  Field IDs are
strictly increasing, so each request sequence is greater than the preceding one
regardless of value.  Split every 64-bit value into exact low/high 32-bit fields.
EL2 prints each accepted receipt sequence before the driver proceeds.  Only the
first non-paging submission is claimed atomically.

WHAT IS STILL UNKNOWN:

- exact Submit flags, context, node/engine/fence, DMA/private ranges and endpoints;
- whether private BLT recognition succeeds;
- dispatcher route;
- first failing PresentSubmit guard, or render/paging status if another route is
  selected.

## Implementation and verification

1. Add a portable trace-word ABI with fixed field IDs and a decoder test.
2. Add an `AppleAgxSubmitQualification` MSBuild property/switch.  Normal builds
   compile all trace call sites away.
3. In the qualification build only, emit exact scalar inputs, private shadow
   classification, route, numbered PresentSubmit guard and returned status.
4. Preserve the original short-circuit order and return values.  Do not suppress
   or replace the failing status.
5. Run the codec/profile RED then GREEN, relevant render tests, pinned WDK build,
   analysis, Universal validation, signing, version and hash gates.
6. Before hardware, preregister exact source/platform/package/recovery identity.
   Verify ordinary Code28/no-package baseline and both control planes.
7. Stage only the exact EXP507 package, graceful restart, one logged full-owner
   launch, decode the first complete trace, collect Windows evidence, then exact
   cleanup and restore ordinary GPU-visible baseline.

PASS: the host log contains a complete, internally consistent first-submit trace
that identifies one exact route/guard/status without changing the functional
boundary.  FAIL/INCONCLUSIVE: missing or stale sequence, candidate never reaches
Submit, or the trace cannot distinguish the guard.

Recovery: exact-package lifecycle, ordinary 377/392 GPU-visible cleanup first;
immutable 377/385 GPU-hidden recovery only if the installed package prevents SSH.

WHAT REAL BUG OR INVARIANT WILL THIS TEST CATCH?  The codec/profile test catches
field collisions, non-monotonic request sequences (which EL2 rejects as stale),
loss of exact low/high halves, or accidental diagnostic inclusion in ordinary
FullProduction builds.  It does not manufacture a behavioral render test for a
receipt-only experiment.

## Offline implementation result

Implemented as a qualification-only profile with no m1n1/Mu/ACPI change.  The
normal profile does not define `APPLE_AGX_SUBMIT_QUALIFICATION`.  Private-shadow
classification preserves the original short-circuit order; the traced
PresentSubmit path preserves every original return status and adds only numbered
guard receipts.  A decoder accepts only successful QUERY receipts in power state
ON and rejects duplicate/non-monotonic fields.

Verification before the pinned Windows build: 92 render tests PASS, including
the exact trace codec, host-log decoder, profile isolation, valid Present path,
unresolved-residency guard and DMA-start guard.  The selected 12 WDDM/shared
tests PASS.  Scoped `git diff --check` and Python parser compilation PASS.
