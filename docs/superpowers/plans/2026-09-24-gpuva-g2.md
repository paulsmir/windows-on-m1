# GPUVA G2 broker extension implementation plan

> **For agentic workers:** Execute the checked steps inline in this worktree. Hardware use requires separate preregistration.

**Goal:** Preserve the EXP769 context0 hash response, add independent process TLB flush, and enforce guest IPA backing for process PTE publication.

**Architecture:** m1n1 remains the owner of stage-2 translation, UAT roots, ASID slots, TLB acknowledgement, and recovery. The versioned broker wire gains a flush verb; the KMD client uses the same shared header. Context0 and firmware TTBR1 remain read-only. The G3 KMD will pass system/aperture guest IPA or a resolved local-reserve IPA to the broker.

**Tech Stack:** C11 broker/host tests, ARM64 m1n1, shared C ABI, Python unittest harness.

**Spec:** `docs/superpowers/specs/2026-09-23-gpuva-broker-v5-design.md`, `docs/superpowers/specs/2026-09-24-gpuva-g3-contract.md`.

## Global constraints and inspected sources

- Hardware: EXP767 two process-root jobs and retirement; EXP768 pre-DriverEntry stall with KD; EXP769 Stage4 hash-before refusal and exact Code28 recovery.
- Asahi: `.local/reference/asahi-linux-asahi/drivers/gpu/drm/asahi/mmu.rs` flushes the owning ASID/slot and checks the active slot before firmware cache flush; no code is copied.
- m1n1: `src/hv_agx_gpuva_v5.{c,h}`, `src/hv_agx_retained_platform.c`, `src/hv_agx_retained_root.c`; `translate_guest` already walks the whole aligned 16-KiB guest stage-2 span and rejects private/nonallocated regions through launch-memory policy.
- Mu: `J313AppleAgxAbiAdmission.asl.inc` exposes APPL0002 and the broker resource; it owns no runtime mapping or flush.
- Windows: pinned WDK26100 and Microsoft `DXGK_BUILDPAGINGBUFFER_FLUSHTLB`, `DXGK_BUILDPAGINGBUFFER_UPDATEPAGETABLE`, `DXGK_PTE` documentation. VidMm owns GPUVA, while KMD resolves segment address and m1n1 validates guest IPA before GPU PTE publication.
- Keep context0/TTBR1 untouched; version the ABI; no hardware launch in this plan. The smallest hardware checkpoint after offline verification is one registered process/root/update and explicit flush with matching EL2 receipt; failure leaves pages owned until reset and uses frozen EXP377/392 recovery.
