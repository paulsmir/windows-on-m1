# GPUVA G3b Windows admission implementation plan

> **For agentic workers:** Execute inline in the existing integration worktree; user approval A/B already covers the broker and G3 discriminator. Keep caps disabled until every advertised DDI has an executable path.

**Goal:** Admit WDDM GpuMmu with truthful VidMm page tables, process roots and one hardware checkpoint without rendering.

**Architecture:** VidMm owns process GPUVA and invokes WDDM callbacks. KMD resolves local segment offsets to the 64-MiB reserve's guest IPA, passes system/aperture guest PA unchanged as IPA, and tracks every table, backing and context per process. m1n1 ABI6 validates stage-2 backing, publishes AGX UAT entries and acknowledges ASID flush. The KMD retires mappings, grants and child tables before `DESTROY`; failed exchanges preserve owned pages and poison submission until recovery. Mu describes APPL0002 and does no runtime GPUVA work.

**Tech Stack:** C11 shared library and host ASan/UBSan tests; pinned WDK 10.0.26100.0 ARM64 KMD; signed Windows package; EXP377/392 recovery.

**Spec:** `docs/superpowers/specs/2026-09-24-gpuva-g3-contract.md`.

## Inspected sources and contract

- Hardware: EXP767 proved two slot1 process-root TA/3D jobs, completion, JOB_END, RELEASE and TLB ack; EXP769 exposed table teardown BUSY with no job and restored ordinary Code28. No GpuMmu package has run.
- Asahi: `.local/reference/asahi-linux-asahi/drivers/gpu/drm/asahi/{mmu,pgtable}.rs` uses 39-bit VA, 16-KiB leaves, three levels, owning ASID/slot flush and unmap before VM release. Use behavior as evidence; no source copy.
- m1n1: `m1n1_windows/src/hv_agx_gpuva_v5.{c,h}`, `hv_agx_retained_platform.c` own guest stage-2 validation, process root, table/leaf publication, slots and FLUSH_TLB. Context0 and TTBR1 stay firmware-owned.
- Mu: `mu/.../J313AppleAgxAbiAdmission.asl.inc` exposes one APPL0002 and broker resource, without runtime ownership.
- Windows: pinned `d3dkmddi.h` SHA256 `c13cecb0ce73e7bbdb6bec8586d05eea31932a8c532bec49b3dae4a03054770e`, `d3dukmdt.h` SHA256 `d1c43d619589c2eb3f47877bba6d48735c7f26644fed44a5bb682f9e591eb33f`, `dispmprt.h`; Microsoft GPUMMUCAPS, UPDATE_PAGE_TABLE, FLUSH_TLB, DXGK_PTE, CreateProcess, SetRootPageTable and SubmitCommandVirtual documentation. Leaf input is logical 4-KiB entries; contiguous allocation offsets do not guarantee physical contiguity. `SetRootPageTable` is VOID and must poison later work on failure. `SubmitCommandVirtual` may return only success or invalid parameter without bugcheck.
- Existing KMD: `driver.c`, `lifecycle.c`, `callbacks.c`, `paging_windows.c`, `memory_runtime_windows.c`, shared B1 v5 client/roots/submission and G3a translator. Physical WDDM remains the stable profile. Compare to EXP767 launch contract and physical milestone before package build.
- Smallest hardware checkpoint: natural StartDevice/Code0 with GpuMmu caps, then observed CreateProcess, SetRootPageTable, UPDATE_PAGE_TABLE, FLUSH_TLB and DestroyProcess, no GPU job. On failure collect raw evidence before exact package rollback to ordinary GPU-visible Code28; use GPU-hidden only if ordinary recovery cannot reach SSH.

## Offline implementation result (2026-09-24)

The G3 qualification profile now compiles and links on the pinned WDK26100
ARM64 builder with zero warnings/errors. Host sanitizer tests exercise the
address translator and real shared v5 process graph, including direct remap,
slot lease, job retirement and leaf/grant/parent/table/root teardown. The full
1019-test run adds no failing test name over the pinned baseline. The supported
virtual submit format is the existing prepared GDI DMA shadow with a mapped
process DMA range and contiguous local output; Mesa VA command generation is
still G4. `G3Armed` gates StartDevice before broker MMIO in the recovery guest.
No G3 package has been installed on Air; the hardware checklist above remains
open until its separately registered discriminator is complete.
