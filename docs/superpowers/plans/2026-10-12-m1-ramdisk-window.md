# M1: окно ramdisk только при загрузке с ramdisk

Дата: 2026-10-12. Шаг M1 плана `2026-10-11-agx-driver-roadmap.md`. Источник фактов:
`investigation/analysis/M1-ramdisk-window-survey.md` (разбор m1n1, Mu, `run_uefi.py`, тестов
и конвейера стенда).

## Что сейчас

- Mu PEI (`MemoryInitPeiLib.c:405-412`) всегда резервирует 1 ГиБ 0x860000000-0x8A0000000, если
  PCD задан, и не читает заголовок `ASIRAMDK`; это делает только DXE
  (`BootRamdiskHelperDxe.c`).
- m1n1 всегда запрещает GPU-backing в окне (`hv_agx_retained_platform.c:61-63`,
  `hv_agx_power_mmio.c:70-73`), потому что дескриптор запуска не знает о ramdisk.
- О наличии ramdisk знает только запускающий (`run_uefi.py --ramdisk`); без ramdisk он
  заголовок не стирает.

## Кто чем владеет

| Решение | Владелец | Канал |
|---|---|---|
| есть ли ramdisk | запускающий (`run_uefi.py`; standalone m1n1 — никогда) | дескриптор запуска (доверенный, до входа в гостя) и заголовок в окне |
| карта памяти ОС | Mu PEI | HOB с решением для DXE |
| DMA GPU в окно | m1n1 (EL2) | регион нового вида в дескрипторе |

EL2 не доверяет заголовку в RAM гостя: гость может его писать.

## Изменения

1. **`run_uefi.py`:** проверка образа до публикации дескриптора; с `--ramdisk` — регион
   `HV_CONTRACT_REGION_RAMDISK` (база и размер окна) в дескрипторе; без него — обнулить
   страницу заголовка (и сбросить её из кэша: PEI читает с выключенным MMU).
2. **m1n1:**
   - новый вид региона в `hv_launch_contract.h`;
   - `hv_agx_retained_backing.c` принимает его, и существующая проверка пересечений
     запрещает backing;
   - убрать безусловные исключения `J313_AUTONOMOUS_LAYOUT.ramdisk_*`; инварианты
     раскладки (`excluded[0]`, `hv_autonomous_runtime.c:228`) не трогать;
   - standalone-путь обнуляет страницу заголовка при запуске гостя.
3. **Mu:**
   - общий предикат заголовка (магия, границы размера, переполнение) в `PreloadedRamdisk.h`,
     как в ans-native;
   - PEI резервирует окно только при истинном предикате и публикует GUID HOB с решением;
   - `BootRamdiskHelperDxe` берёт решение из HOB;
   - исключение окна из локального резерва GPU остаётся безусловным.
4. **Не меняется:** JSON раскладки, PCD, сгенерированные файлы, хэш раскладки ANS, KMD.

## Тесты (RED -> GREEN, детерминированные контракты)

- `run_uefi.py`: дескриптор содержит регион ramdisk тогда и только тогда, когда есть
  `--ramdisk`; без него страница заголовка обнуляется (dry-run, `test_public_scripts.py`).
- m1n1: `hv_agx_retained_backing_test` — страница в регионе ramdisk запрещена, та же
  страница без региона разрешена.
- Mu: хост-тест предиката заголовка (магия, size 0, size > MaxSize - 0x1000, переполнение)
  и решения PEI; связка байтов заголовка `run_uefi.py` и `BootRamdiskHelperDxe.h`.

## Сборка и стенд

- m1n1: точная строка 98cdabae (`make -j8 IOMFB_FULL_OWNER=1 AGX_LOCAL_RESERVE_V2=1 ...`),
  новый `m1n1-build-info.json`.
- Mu: флаги EXP856 `build-mu.sh` на сборщике; AML должен совпасть с `3bdb28ed`.
- В эксперименте: `full-owner<X>.sh` (пути m1n1 и FD), `hardware-manifest.json`,
  `manifest.json` (теперь пишется из скрипта запуска).

## Проверка на железе (одна переменная: m1n1 + Mu + `run_uefi.py` M1 вместе)

Контрольная точка обычной загрузки:
- в логе нет "reserving preloaded RAMDisk window", `regions=8`;
- Windows видит ровно на 0x40000000 больше RAM;
- smoke, timedemo и copybuffer как в EXP1222.

Отказ — откат через `rec<X>h`. Профили восстановления используют старые m1n1/Mu и основной
`run_uefi.py`, M1 их не затрагивает. Загрузку WinPE с новым комплектом проверить отдельным
шагом (ANS).

## Риски

- Mu без m1n1 ломает GPU: backing в окне будет отклонён, а сброс TDR неисправим. Поэтому
  m1n1 и Mu меняются только вместе.
- Старый m1n1 с новым `run_uefi.py --ramdisk` отклоняет неизвестный вид региона. На
  восстановление это не влияет: оно использует основной `run_uefi.py`.
- Скрытый профиль восстановления запускает `run_uefi.py` этого worktree с m1n1-exp377: нужен
  dry-run устаревшего пути дескриптора.
