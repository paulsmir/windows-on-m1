# R89 scanout address and EXP806 discriminator

## Evidence and primary sources

EXP805 had APPL0002 Code0, AppleAgxAdmission Running, CDD BltToPrimary and Present ETL events, KMD source address Segment2 `0x1500030000` Status0, and DCP A408/D589 latch. The operator saw backlight on and a black panel. The old physical path showed the same symptom. This does not identify whether scanout bytes, DART translation, or DCP state are wrong.

Inspected `display.c` and `scanout_windows.c`, `apple_agx_local_segment.c`, `memory_runtime_windows.c`, `physical_memory_windows.c`; m1n1 `hv_agx_scanout_{broker,service}.c`, `hv_agx_power_mmio.c`, `display.c`, DCP IOMFB owner; EXP805 host and guest receipts. Microsoft [DXGKARG_SETVIDPNSOURCEADDRESS](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/ns-d3dkmddi-_dxgkarg_setvidpnsourceaddress) defines `PrimaryAddress` within `PrimarySegment`. Asahi [plane.c](https://raw.githubusercontent.com/AsahiLinux/linux/asahi/drivers/gpu/drm/apple/plane.c) supplies a DMA address plus framebuffer offset to DCP; upstream [m1n1 display.c](https://raw.githubusercontent.com/AsahiLinux/m1n1/main/src/display.c) maps framebuffer PA to a common DCP/display DART IOVA. No external code is copied.

## Address contract

KMD's Segment2 base is `0x1500000000` (its local GPU VA), so observed `PrimaryAddress=0x1500030000` becomes surface offset `0x30000`, not an IPA or PA. KMD registered its local pool using `GuestIpaAddress` from the contiguous ADL allocation. m1n1 validates each 16 KiB IPA page with `hv_ipa_to_pa`, requires contiguous RAM PA, allocates a DCP IOVA, and maps PA at that IOVA in both display and DCP DARTs. The present request carries only `SurfaceOffset`; the service calls `present_begin(pool_iova + offset)`. `display_scanout_present_begin` passes this IOVA to IOMFB. The DCP never receives `0x1500030000` directly. The exact runtime PA/IOVA pair is not currently in the EXP805 guest receipt; EXP806 must log it at the swap boundary.

VidMm owns segment addresses and primary lifetime; KMD owns validating the Segment2 offset and presentation request; m1n1 owns stage-2 IPA-to-PA translation, DART mappings, DCP IOVA, and physical swap/latch. Mu/ACPI only expose the existing APPL0002 full-owner profile and are unchanged. The local physical object uses `DXGK_MEMORY_CACHING_TYPE_NON_CACHED`. EXP803B's `Cached` CDD shadow belonged to the Microsoft software adapter, not proof that Apple's local scanout pool is cached. Neither the KMD source-address path nor m1n1 normal present path flushes CDD shadow bytes into the Apple pool. That is a separate content hypothesis.

## EXP806 single variable

Keep package804, Mu and recovery artifacts unchanged. Build an m1n1 full-owner image differing only by an experiment-gated pattern at the physical present boundary. Immediately before every DCP swap, fill the validated `pool_pa + SurfaceOffset` with red/green/blue/white vertical BGRA8888 stripes, clean that physical range to PoC, issue a DMA write barrier, and log pool IPA, PA, surface PA, surface IOVA, offset, dimensions and four sample pixels. The code must fail closed if size/range/format or mapped address is invalid; production profile has no pattern. This host-side placement uses m1n1's proven PA and DART IOVA rather than guessing a Windows CPU mapping. Host tests exercise stripe bytes, bounds and the pre-swap callback order.

The falsifiable hardware checkpoint is pinned SSH, Code0/Running, host pattern receipt followed by A408/D589 latch, then operator observation while LOOK_NOW is active. Visible stripes support the DCP address path and shift the target to CDD primary contents/copy/cache. A black panel despite those receipts supports a DART address or DCP plane issue. Neither outcome alone proves a final fix. On failure collect guest receipt/ETL and host logs first, then exact package cleanup and frozen ordinary Code28; R60 hidden dump-first rules apply if arm consumption or package identity is uncertain.
