# EXP808 — delayed read-only primary snapshot

WHY THIS HYPOTHESIS: (1) EXP807 saw 4,096,000 zero pixels at selected PA `0x9bc020000` immediately before the only swap, with exact DCP latch. (2) The same run's ETL recorded CDD Blt/Present around the second boot marker, but there is no host UTC timestamp for the snapshot. (3) The selected primary was never sampled after latch, so a late CDD write and a separate shadow allocation remain distinguishable.

Sources inspected: EXP807 hardware ledger and compact GPU state; R90/R90a review; KMD `scanout_windows.c`, `display.c` and source-address receipt; m1n1 `hv_agx_scanout_broker.c`, `hv_agx_scanout_service.c`, `hv_agx_power_mmio.c`, `display.c`, and the service call site in `hv_exc.c`.

R91 offline Blt check: Apple `AdmissionDdiPresent` can prepare a Blt command. The physical `AdmissionDdiSubmitCommand` routes a valid Present packet through `AdmissionPresentSubmitTraced` to the CPU queue, whose worker calls `AdmissionMemoryRuntimeExecutePresent` and writes the resolved local destination. The G3 `AdmissionDdiSubmitCommandVirtual` non-system route currently requires `Flags.Value==0` and sends its packet to the render queue; it does not route a Present Blt. EXP807 did not receipt an Apple Present packet or an executed Blt, so this difference is a precise candidate, not a proven cause. If the delayed primary stays zero, next instrumentation must record each executed Blt source and destination PA/CPU, byte count and clean status and compare its destination with the selected primary PA.

Observed contract: Windows CDD owns the Blt/Present events; Apple KMD selected segment2 offset `0x30000` and mapped the primary to CPU/PA `0xffffdf7035430000`/`0x9bc020000`; m1n1 translated that PA to DCP IOVA `0x101c0000` and latched swap_id10. Mu and ACPI are frozen. No layer performs an explicit clean of CDD CPU writes in the proven path. The D3DDDIFMT21→BGRA byte order matches DCP `FMT_BGRA`; panel water damage precludes color inference from EXP806's photo.

Experiment: keep exact package807, Mu and recovery. Change only the m1n1 diagnostic image: retain the pre-swap read-only sample and take one more sample of the same validated PA 15 seconds after exact latch while the full-owner guest is alive. No pixel write, cache clean, DART remap, format or caps change. Cancel the delayed read if the pool is released or the latched sequence changes. A nonzero late sample supports a late producer write or cache visibility branch; persistent zero with current-boot CDD activity supports a separate CDD shadow/no-copy branch. Neither outcome alone is a license to guess a Windows interface.

Smallest checkpoint: host pre/late pixel counts and hashes with same PA/IOVA, DCP A408/D589, pinned SSH Code0, current-boot ETL, and LOOK_NOW/LOOK_DONE. Preserve exact image/package hashes and return by disarmed same-profile reboot, exact package cleanup, then ordinary GPU-visible Code28; hidden image remains emergency recovery.
