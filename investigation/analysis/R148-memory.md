# R148 memory lifetime analysis and implementation plan

EXP861's saved ETL proves repeated shared-allocation retention on DWM's long-lived consumer device after the producer devices have been destroyed. It does not prove physical-memory exhaustion or explain the later SSH loss. The current Mesa Flush path has a deterministic deferred-resource cleanup omission that matches this retained-owner pattern.

## Source-first plan (before implementation)

Inspected `mesa/winsys/agx_d3d10_windows.cpp` (PresentationDestroy, collect_presentations, FlushStatus, flush_retire, device teardown); `mesa/scripts/build-native-asahi-state.py` (actual frontend Flush/OpenResource/DestroyResource injection); `render-admission/umd/src/{umd.c,umd_resource_lifetime.c,umd_runtime_device.c,umd_win32_screen.c}`; `render-admission/src/{allocation_windows.c,gpuva_g3_windows.c,memory_runtime_windows.c}`; shared-resource regression at `umd_contract_windows.c:3776,3794`. Primary Microsoft contract: https://learn.microsoft.com/en-us/windows-hardware/drivers/display/changes-from-direct3d-10 and https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dumddi/nc-d3dumddi-pfnd3dddi_deallocatecb . Microsoft requires deferred shared-resource deallocation during Flush, including empty command buffers, after immediate-context references are resolved.

Observed ownership: UMD holds the runtime resource and defers DeallocateCb; the native BO/source/submission lifetime gate decides when a presentation can enter the retirement queue. Dxgkrnl owns shared-global/per-device allocation references and eventual global destruction. KMD Open/Close counts mirror those references and DestroyAllocation must not bypass outstanding opens. R137 private storage is a suballocator of the fixed reserved private pool, not a new VidMm allocation on each device. Asahi's native resource lifetime is retained; no hardware protocol, m1n1, Mu, initialization, DMA, IRQ, power or recovery behavior changes.

Defect: collect_presentations queues shared resources through AdmissionUmdDestroyResource. Production AdmissionUmdRetirementDrain is only reached by the legacy umd.c Flush. The Mesa frontend calls FlushStatus and query cleanup instead. Even flush_retire collects without draining. Eligible resources therefore remain until device finalize. Existing native shared tests manually drain the internal queue, hiding the public Flush omission.

Minimal implementation: add an explicit Mesa deferred-resource Flush cleanup entry point and invoke it after the normal frontend pipe flush/status succeeds. Collect only resources whose native BO has disappeared; preserve pending native/submit holds and callback failure queue entries. Do not wait for unrelated GPU work, synthesize completion, alter residency or change caps. Regression executes actual collection, resource destruction, retirement helper, and generated frontend Flush bodies; additionally replace the native Windows test's manual drain with public pfnFlush.

Falsifiable future checkpoint (not authorized/run here): with the independently hash-verified candidate and ordinary recovery available, repeated shared producer-destroy / consumer Flush should close consumer aliases after native holds retire. ETL plus a bounded retirement receipt should show queued/deallocated counts and bytes converge while retained sources remain protected. Rollback uses the existing exact-package/Code28 contract. A full 627-second claim requires tracing across that actual interval.

## Implemented offline

Added explicit `AgxD3d10WindowsFlushDeferredResources` and invoked it only after normal frontend pipe Flush/status succeeds. It collects eligible presentations using the existing native-registration gate, then uses the existing retirement drain; a failed callback keeps the exact record queued. Pending/uncertain native resources remain held. The existing two-device Windows test now uses each device's public `pfnFlush`, not private drain calls. No hardware/package/commit performed by this task.

`python3 -m unittest discover -s tests -p test_r148_shared_retirement.py`: RED produced the intended runtime assertion that the empty Flush never closed its retired shared alias; GREEN passed. The harness compiles the actual collector, DestroyResource, retirement implementation and generated frontend Flush; tests live native hold, empty Flush after native release,64 cycles, callback failure/retry and terminal failure. `git diff --check` passed. Adjacent frontend prepare test had one pass and one environment error: missing worktree `.local/reference/mesa`; it did not reach changed frontend generation. Full native Windows two-device test and ARM64 compile/analyze remain for root integration.

Causal confidence: the steady-state UMD Flush omission is proven by source, official contract and executable replay. EXP861's early retained shared aliases support it as a cause of growth, but ETL ends before the measured478-second interval and has no queue receipt; exact attribution of all4.46GB and SSH loss remains unproved. If measuring this candidate, a bounded lifetime receipt should include device generation, pending presentation count/bytes, queued retirement count/bytes, deallocate attempts/success/fail/status and first retained resource identity, alongside system free/commit-limit counters and trace spanning the endpoint.
