# EXP900: do not poison the native context on an empty flush

## Primary sources and observed contract

EXP899 original UMD receipts prove that live DWM enters native `_Present` with `agx_context.any_faults=1` before `AgxWin32AsahiContextFlushForPresent`, while backend failed, batch-present, draws, LastScreenError, and DrawTerminal are all zero. The context-flush call returns `E_FAIL`; `FlushStatus` and `pfnPresentCb` are not reached. No receipt identifies the first setter of `any_faults`, so the following is a **falsifiable owning-layer hypothesis**, not a claim of a proven DWM writer.

The exact generated native `agx_pipe.c` from package899, SHA `c357dd22b006a5e1c81bba6844a96e36205afed65f3f7b4fb03aa812ad689007`, comes from `drivers/apple-agx/mesa/scripts/native-asahi-batch-lifecycle.py`. Its `agx_flush_batch` marks a context fault for an active batch with zero draws, aborts/resets that batch, and leaves backend failed=false. This produces precisely the DWM pre-Present state. The pinned upstream Asahi/Mesa `agx_pipe.c`, SHA `e29b0c206bdadfa14de83c439526fef5f8d8650a3f7ae223aa2e8e945386d86e`, explicitly resets an active batch without GPU work (`!has_cdm && !has_vdm`) and returns without fault. Existing `agx_win32_gpuva_batch.c::AgxWin32AsahiBatchAbort` accepts an unsubmitted capsule. The native frontend's generated `Device.cpp::Flush` can call `pipe->flush` before DXGI Present, so empty-batch flush is reachable through Windows without changing DXGI caps. The pinned WDK D3D10 frontend owns its `pfnFlush`/error callback; this is FULL GRAPHICS UMD batch-lifecycle behavior, not a DISPLAY_ONLY or KMD contract. The observed driver model, package signing, m1n1 DCP measurement firmware, Mu R143/ACPI, interrupts, UAT and GPUVA broker remain unchanged.

`WINDOWS CONTRACT:` a flush with no GPU work must not corrupt the UMD context or prevent later DXGI Present; actual failed GPU work still reports through the existing error path. `AGX/ASAHI CONTRACT:` upstream Asahi resets a no-work batch without submission; the Windows GPUVA capsule must be aborted before reset and an unabortable capsule remains a fault. `TRANSLATION:` in the generated Windows `agx_flush_batch`, recognize only an active zero-draw batch with no CDM work and no initialized/clear VDM work, abort/reset it without setting `any_faults`, and preserve the old fail-closed path for drawn, compute-only, initialized/clear, or unabortable work. Do not touch KMD Present, DXGI registration, source rectangles, m1n1 or Mu. `WHAT IS STILL UNKNOWN:` whether the live DWM's first context fault is this empty-batch branch rather than another setter. A behavior-only package experiment is justified to check whether DWM's first Present changes from preFault1/E_FAIL to preFault0 and reaches `pfnPresentCb`, then KMD Present and nonzero current DCP scanout.

## Regression and hardware checkpoint

`WHAT REAL BUG OR INVARIANT WILL THIS TEST CATCH?` The extracted actual generated `agx_flush_batch` branch previously poisoned an active zero-work batch, permanently making later Presents fail. The ASan/UBSan C replay failed before the fix, then passed with no-work abort/reset preserving a clean context. It also verifies initialized VDM work, compute work, and drawn work without VDM still fault, while failed abort remains a fault. This is RED→GREEN on a deterministic native lifecycle invariant, not a synthetic protocol test. No external Asahi code is copied into this repository; the change is confined to the existing generated overlay.

The smallest hardware checkpoint is one package-only EXP900 change over EXP899: first live DWM `_Present` internal context receipt (pre/post fault, backend, batch), `pfnPresentCb` and KMD DDI counters, and matched current DCP late +120/+300/+600 nonzero pixels. If preFault remains1, the empty-batch bug was real but not sufficient for DWM; do not stack another behavior change. If it becomes0 but a later callback fails, analyze that newly exposed boundary offline. Preserve original and hidden host size/SHA evidence before exact Code45 package cleanup; ordinary GPU-visible Code28/package0/autologon1 recovery is mandatory. The immutable GPU-hidden image remains emergency-only.
