# EXP963 — identify the resource handle origin at failed retirement

Classification: FULL GRAPHICS diagnostic. EXP962 reproduced `pfnDeallocateCb` `E_INVALIDARG` for full runtime `hResource=0x000002bc95d26600` while the existing bounded KMD registry failure receipts remained at Count 0. The KMD processed other destroys successfully. The Direct3D runtime/dxgkrnl path rejected that request before KMD or after a successful KMD return; exact ordering is not proven. A separate DWM minidump again shows a low32 uDWM pointer, writer unknown.

WINDOWS CONTRACT: Microsoft documents that CreateResource(D3D10/D3D11) and OpenResource provide distinct runtime resource handles and that the UMD passes the same handle to `pfnAllocateCb` (for creation) and later `pfnDeallocateCb`. Shared resources can retire during Flush after command submission; non-shared primaries require synchronous deallocation. `pfnDeallocateCb` returning `E_INVALIDARG` means the runtime validated invalid parameters. The pinned WDK26100 defines the exact handle fields.

AGX/ASAHI CONTRACT: unchanged native AGX batches, UAT, RTKit, GPU memory, DCP, interrupts and power. The current m1n1 and Mu implementations do not own Windows runtime resource handles. No hardware or firmware field changes.

TRANSLATION: Existing `ADMISSION_UMD_RETIREMENT` already retains full runtime handle, KMD resource/allocation handles, Primary/Shared flags and queue order. Add an internal `Origin` value (Create or Open) at the two creation sites. On a failed `AdmissionUmdRetirementDrain` callback only, emit those existing fields with the full 64-bit runtime handle and queue count. Give this failure-only stage its own bounded 16-record diagnostic allowance, so startup chatter cannot suppress it as in EXP959. Preserve the return result, callback order, requeue and every GPU/Windows behavior. The earliest failed handle's origin will decide whether to inspect the Create/pfnAllocateCb association or the OpenResource view lifecycle; it will not by itself prove the writer of DWM pointer corruption.

WHAT IS STILL UNKNOWN: exact handle origin and allocation association at the first callback refusal, runtime validation predicate, and independent DWM pointer writer. Hardware is justified only to observe the undocumented runtime validation path after deterministic source and WDK mapping. Checkpoint: first UMD stage2 E_INVALIDARG plus matching retirement-origin receipt in a short full-owner boot; collect/halt and exact package rollback in Code43, durable Code28. If failure does not recur, mark inconclusive and do not rerun the same probe without new evidence.
