# EXP899 native Present subcall discriminator

## Source-first boundary

EXP898's original host-verified UMD log shows DWM PID 1232 repeatedly entering the native `_Present`, reaching `AgxD3d10WindowsPresentationSubmit`, and returning `E_FAIL` before `pfnPresentCb`. No uncapped receipt distinguishes `AgxWin32AsahiContextFlushForPresent` from `AgxD3d10WindowsFlushStatus`. The former, in `drivers/apple-agx/mesa/winsys/agx_win32_asahi_scene.c`, returns false on null context, a faulted native context after a drawn flush, an unabortable non-drawn batch, or a residual batch/fault after abort. The latter, in `drivers/apple-agx/mesa/winsys/agx_d3d10_windows.cpp`, returns failed render/post status or the backend/draw-terminal LastScreenError. The generated native DXGI frontend calls only these two before `AdmissionUmdSubmitPresent`. Existing `AgxWin32AsahiContextDiagnostic` already reads fault/backend/batch/draw state without changing it. No current source or original trace proves which predicate fired; one offline comparison pass is exhausted.

`WINDOWS CONTRACT:` FULL GRAPHICS DXGI native `_Present` must either reach `pfnPresentCb` after successful rendering or return a truthful failure. The observed `E_FAIL` is pre-callback, so changing KMD Present or scanout cannot repair it. `AGX/ASAHI CONTRACT:` native context flush is responsible for completed/rejected batch state; shader variant failures set `any_faults` and backend failed, while GPUVA batch refusals are separately logged. No m1n1/Mu/firmware state changes. `TRANSLATION:` add bounded process-local receipts only after `ContextFlushForPresent` and `FlushStatus`, with pre/post context fault, backend failed, live-batch/draw state, batch status and LastScreenError; return values and control flow remain byte-for-byte equivalent. `WHAT IS STILL UNKNOWN:` which subcall first returns failure for live DWM and whether its native context was already faulted before Present. Hardware is justified solely for this unobservable UMD ordering/state boundary.

`WHY THIS HYPOTHESIS:` (1) EXP898 proves DWM calls native Present yet gets pre-callback `E_FAIL`, excluding missing DXGI entry and KMD Present as the first defect; (2) exact current implementation has only two remaining failing subcalls, and all successful normal state logs are suppressed after 128 process records; (3) no DWM `reject-batch` record appears, making a shader/context fault or unlogged FlushStatus more likely than a GPUVA batch refusal, but not yet proven. Single variable: two passive bounded UMD subcall receipts. Keep R177 receipts, KMD DDI probe, pinned firmware/Mu/caps/behavior unchanged.
