# EXP901: first native context-fault setter

## Source-first boundary

EXP899 and EXP900 original UMD receipts independently prove live DWM enters native `_Present` with `agx_context.any_faults=1`, backend failed=0, batch=0 before `ContextFlushForPresent`. R179 clean no-work flush preserves that state, excluding its empty-batch path as sufficient. The exact package900 generated Mesa sources have multiple remaining `ctx->any_faults = true` sites in `agx_batch.c`, `agx_pipe.c`, and `agx_state.c`, including draw admission, clear, flush, render submission, and shader failures. The generated overlay and `agx_win32_gpuva_batch.c` own those transitions; the current normal diagnostic budget obscures which occurred first. The pinned upstream Asahi/Mesa no-work reset contract and exact R179 extracted-body replay have already been inspected. m1n1 measurement firmware SHA d3e0f999, Mu R143/ACPI, DCP, UAT, interrupts, power, and recovery are unchanged.

Include generated file/site and pipe-context pointer, then include the same pointer in the existing Present context receipt for correlation. Log at most 128 first transitions per process to avoid unbounded trace growth. No guard, return, callback, capability, batch lifetime, KMD, firmware, or Mu changes. `WHAT IS STILL UNKNOWN:` the first site for the *same DWM context* that later fails Present. A single receipt-only original boot resolves that ordering; do not infer it from unrelated process/context faults.

One EXP901 package/boot with first DWM fault-site-to-Present-context pointer correlation is the smallest discriminator.
