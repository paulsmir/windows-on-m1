# EXP966: DWM persistent system-memory leaf discriminator

WHY THIS HYPOTHESIS: EXP965's persisted KMD receipt counted 149376 unpublished GPUVA groups for segment0/system and zero for segment1/aperture. `AdmissionG3UpdateLeaf` accepts Windows 4KiB PTEs but only publishes a complete aligned quartet backed by 16KiB contiguous IPA; it returns success after incomplete quartets. Both EXP964 (GDI cap1) and EXP965 (cap0) have black large physical surfaces, so GDI opcode dispatch alone does not explain them. However the count is cumulative across all processes and may reflect temporary partially populated tables; it does not yet implicate DWM's live graphics.

WINDOWS CONTRACT: Microsoft GPU Virtual Address and GPU Segments documentation says system memory is allocated at 4KiB granularity and valid GPUVA PTEs reference system memory or segment offsets. A KMD that advertises GpuMmuSupported must realize mappings needed for GPU access or reject them; returning success while silently leaving needed mappings absent cannot be assumed safe. Windows may update four logical PTEs in separate calls. Sources: https://learn.microsoft.com/en-us/windows-hardware/drivers/display/gpu-virtual-address ; https://learn.microsoft.com/en-us/windows-hardware/drivers/display/gpu-segments ; https://learn.microsoft.com/en-us/windows-hardware/drivers/display/gpummu-model ; pinned WDK DXGK_PTE and DXGKARG_BUILDPAGINGBUFFER.

AGX/ASAHI CONTRACT: Asahi `drivers/gpu/drm/asahi/mmu.rs` and current AGX UAT encode a native 16KiB page for each leaf; m1n1 `hv_agx_gpuva_v5.c` verifies 16KiB-aligned contiguous IPA and physical backing when registering/updating a leaf. Mu's APPL0002 ACPI and m1n1 power/IRQ/DART contract are unchanged. Discontiguous Windows 4KiB physical pages cannot be directly represented by one native AGX leaf. The translation layer must eventually provide coherent 16KiB backing and explicit synchronization or a truthful refusal, not pretend that all valid Windows PTE quartets are GPU mapped.

TRANSLATION: This run changes only a receipt, not mapping behavior. At the existing DWM frame-arm escape, the KMD already has a validated DWM OS PID and G3 process under the process lock. Once per boot, scan that process's current logical leaf PTE quartets and record a bounded summary of nonempty but incomplete segment0 groups, including first allocation handle and four guest IPAs. This distinguishes cumulative transient/global counts from persistent DWM-owned incomplete system leaves at a frame boundary. Keep SupportKernelModeCommandBuffer=0 from EXP965 so the diagnostic candidate advertises no fail-closed GDI acceleration. No WDDM caps, MMIO, queue, DCP or platform change.

WHAT IS STILL UNKNOWN: whether DWM has such incomplete groups at frame-arm time, whether they belong to redirection textures it samples, and whether a read/write bounce translation can preserve Windows coherency. A zero DWM snapshot excludes this route for the observed frame; nonzero persistent groups materially increase its probability but still require an allocation-to-texture link or a controlled pixel test before a functional mapping fix. The first hardware run is receipt-only; collect quickly after Code0 and physical observation, then exact package cleanup. Recovery: immutable GPU-visible ordinary Code43 and durable Code28, hidden only if unrecoverable.

Inspected source: `drivers/apple-agx/render-admission/src/gpuva_g3_paging_windows.c` (PTE validation and group publication), `gpuva_g3_windows.c` (DWM frame arm), `gpuva_g3_private.h` (process shadows), `allocation_windows.c` (segment preference), `memory_runtime_windows.c` (aperture PFNs), `drivers/apple-agx/shared/src/apple_agx_gpuva_g3_translation.c` and graph code, `m1n1_windows/src/hv_agx_gpuva_v5.c`, Mu generated `J313AppleAgxAbiAdmission.asl.inc`; official Microsoft and Asahi sources above. Ownership: Windows/VidMm allocates system pages and emits PTEs; KMD translates; m1n1/AGX enforces native leaf shape; Mu exposes device/resources; Windows guest controls recovery. Smallest checkpoint is a single DWM graph summary. The receipt must not scan unboundedly or alter graph state.
