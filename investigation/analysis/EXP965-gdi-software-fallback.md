# EXP965: stop advertising GDI kernel command buffers

WHY THIS HYPOTHESIS: EXP964 physically shows small taskbar icons while wallpaper and taskbar background are black, despite Code0, DWM lifetime and successful Present. The driver advertises `SupportKernelModeCommandBuffer=1`, but `AdmissionDdiRenderKm` accepts only one ColorFill/PATCOPY command and its patch path requires local segment 2. CPU-visible class0 GDI staging allocations are confined to aperture segment 1. Microsoft says this cap must be reported only with a cache-coherent GPU aperture; our segment descriptor does not declare one. EXP964G proves GDI context and allocation activity, but no completed GDI command receipt; it does not prove which opcode failed.

WINDOWS CONTRACT: `DXGK_PRESENTATIONCAPS.SupportKernelModeCommandBuffer` advertises GDI hardware command-buffer processing. `DXGK_RENDERKM_COMMAND` includes BitBlt, ColorFill, AlphaBlend, StretchBlt, TransparentBlt and ClearTypeBlend. Microsoft requires a cache-coherent aperture for this declaration. The WDDM 1.2 feature table also marks GDI hardware acceleration mandatory for full graphics, so EXP965 may fail admission instead of selecting software GDI; the hardware run must measure that rather than assume fallback. Primary sources: https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/ns-d3dkmddi-_dxgk_renderkm_command ; https://learn.microsoft.com/en-us/windows-hardware/drivers/display/specifying-gdi-hardware-accelerated-rendering-operations ; https://learn.microsoft.com/en-us/windows-hardware/drivers/display/wddm-driver-and-feature-caps ; pinned WDK 26100 headers and project profile.

AGX/ASAHI CONTRACT: Asahi `drivers/gpu/drm/asahi/mmu.rs` maps aligned GPU IOVA/SG memory and enforces GPU cache/TLB maintenance; it has no Windows GDI opcode contract. Current m1n1 `m1n1_windows/src/hv_agx_gpuva_v5.c` owns guest GPUVA envelope/physical backing and RTKit access. Mu generated `J313AppleAgxAbiAdmission.asl.inc` exposes one coherent APPL0002 devnode, mapped AGX resources and IRQ889; no GDI implementation. Current hardware contract was validated by EXP964 Code0/CPU8/Present, but physical large surfaces remained black.

TRANSLATION: Full WDDM KMD owns truthful caps and RenderKm translation. Change only the advertised `SupportKernelModeCommandBuffer` bit from 1 to 0, leaving KMD/UMD implementation, aperture, m1n1, Mu, scanout, source image, signing and test workload unchanged. If Windows admits the driver, compare a short physical panel observation and DWM/Present/Code against EXP964. This tests whether routing GDI away from the incomplete hardware callback changes the black wallpaper. If Windows rejects the adapter, the mandatory full-graphics cap condition is confirmed and EXP965 is rejected without altering any other bit.

WHAT IS STILL UNKNOWN: Windows' actual admission/route decision when a full WDDM 3.x driver clears this bit, and whether physical wallpaper/background pixels become correct. These are internal dxgkrnl and physical-panel observations; one hardware run is the minimal discriminator. Correct wallpaper plus stable DWM would support this boundary; black wallpaper with Code0 excludes the GDI acceleration route and moves to CPU-visible/aperture texture sampling. Failure recovery: exact hash-verified package965 cleanup in GPU-visible ordinary Code43, ordered reboot and durable Code28 preflight; immutable GPU-hidden only if ordinary cannot be recovered.

Source files inspected: `drivers/apple-agx/render-admission/src/lifecycle.c`, `gdi_windows.c`, `allocation_windows.c`, `memory_windows.c`, `receipts.c`; `m1n1_windows/src/hv_agx_gpuva_v5.c`; `mu/Platform/MacBookAirMid2020Pkg/AcpiTables/J313AppleAgxAbiAdmission.asl.inc`; Asahi `drivers/gpu/drm/asahi/mmu.rs`; official Microsoft pages above. Ownership: Windows/dxgkrnl chooses GDI dispatch and VidMm allocation; KMD owns capability declaration and RenderKm/patch; m1n1 owns GPUVA and AGX runtime isolation; Mu owns APPL0002/ACPI resources; guest Windows owns recovery/reboot, host launcher owns proxy transition. No register, IRQ, DMA or power value changed in EXP965.
