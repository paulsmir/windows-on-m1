# EXP906 receipt-only discriminator

**Source inspected:** EXP905 original DWM UMD log and four KMD DDI probes; `drivers/apple-agx/render-admission/src/gpuva_g3_windows.c`, `src/gpuva_g3_paging_windows.c`, `src/callbacks.c`, `src/dwm_ddi_probe_windows.c`, `umd/src/umd_gpuva_windows.c`, `umd/src/umd.c`, `drivers/apple-agx/shared/src/apple_agx_gpuva_g3_graph.c`, the R145 extracted replay, R175 Present fix/report, existing m1n1 retained GPUVA broker and DCP measurement, Mu R143 J313 AGX ACPI, and the pinned WDK DXGI callback types. Microsoft documents that DXGI Present passes the opaque DXGI context unchanged, flushes partial render work before `pfnPresentCb`, and then KMD `DxgkDdiPresent` follows the callback ([DXGI base functions](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/dxgiddi/ns-dxgiddi-dxgi_ddi_base_functions), [WDDM operation flow](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/windows-vista-and-later-display-driver-model-operation-flow)). The callback's S_OK alone does not establish completion at DCP.

**WINDOWS CONTRACT:** A GPUVA allocation may have resident 4 KiB pages without a complete 16 KiB AGX leaf. VidMM controls residency and calls the GPUVA paging DDI. UMD presents on a created context after flushing render work; dxgkrnl schedules the KMD Present after the callback.

**AGX/ASAHI CONTRACT:** The m1n1 broker owns AGX UAT mapping and retained backing; KMD's graph records published 16 KiB leaves while `ResidentPtes` records exact 4 KiB VidMM local backing. Mu exposes one APPL0002 device and does not own the runtime query or Present queue. R175 already uses `ResidentPtes` for a software BLT source, retaining graph publication for the destination.

**TRANSLATION:** R185 (commit `f096b05687f8955bf391a1fa77ec6cf1d94d8cd2`) separately corrects deterministic G3 COPY_QUERY/UPLOAD/DOWNLOAD by validating all 4 KiB resident PTEs under the process lock instead of first requiring a published graph leaf. The extracted real-KMD replay mapped a 64 KiB local allocation to valid scattered 4 KiB backing with an unpublished graph leaf: original query returned C000000D/predicate53, corrected QUERY and UPLOAD pass with exact owner/offset/segment/local bounds still guarded. **R185 is excluded from EXP906.** EXP906 is a diagnostic-only source descendant of exact EXP905 root `526ed752` (`99c9e158`): bounded first-eight per-OS-PID KMD query failures for up to 32 PIDs record allocation/VA/predicate/status/context/generations/walk; UMD logs failed escape HRESULT/handle/operation and Present callback render-fence state. Existing KMD DDI probe records Present, virtual submit counts, last status/context/fence. No caps, admission, queue, broker, firmware, ACPI, or display behavior changes.

**WHAT IS STILL UNKNOWN:** The first DWM copy-query's actual KMD predicate and allocation identity are not proven by the global first-failure receipt. EXP905's first two DWM callback S_OK events did not produce a KMD Present in four later probes; it is unknown whether dxgkrnl deferred them behind a same-context render fence, discarded them after a failed virtual submit, or took another internal path. Later DWM pre-submit copy refusals alone cannot explain earlier accepted callbacks.

**WHY THIS HYPOTHESIS:** (1) EXP905 has DWM `reject-copy-slot` step1/VA C0000 but the adapter-global first KMD predicate53 receipt is VA20000/process9; exact correlation is missing. (2) EXP905 first two DWM `pfnPresentCb` calls returned S_OK, yet KMD Present/virtual-Present counters stayed zero at original boot+241/+412/+620/+823s while non-Present virtual submits advanced, so the queue boundary is real and unassigned. (3) R185 offline RED/GREEN proves one deterministic copy-query defect but cannot identify whether DWM hit it; running R185 and diagnostics together would violate the one-variable rule. The smallest hardware discriminator is one unchanged-behavior receipt-only EXP906 with the live DWM and matched current DCP +120/+300/+600 snapshots.

**Ownership and recovery:** Windows UMD owns render flush, copy request, and DXGI callback; dxgkrnl owns scheduling; KMD owns query provenance, Present/virtual-submit DDIs and fence reporting; m1n1 owns AGX broker/DCP, Mu owns ACPI. Use exact EXP905 firmware/Mu images, preregister package hashes, stage only package906 on the ordinary GPU-visible Code28 guest, launch one full-owner >=750-second window, and independently verify original and hidden host evidence sizes/SHA before any exact Code45 package cleanup. Never remove an AppleAgx package from live Code0; preserve autologon and restore ordinary GPU-visible Code28/package0.
