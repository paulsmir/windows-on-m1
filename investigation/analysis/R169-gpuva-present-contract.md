# R169 GPUVA BLT Present contract and EXP890 live-dump boundary

## Evidence and primary sources

The retained EXP890 Present receipt also has `DmaBufferSegmentId=0`, physical DMA address0 and `DmaBufferGpuVirtualAddress=0x60000`, directly confirming the virtual DMA form of the failed BLT.

EXP890 original Code0 boot has a first retained `Wom1PresentReceipt` Version1/160B, Branch4, `STATUS_INVALID_PARAMETER`, BLT flag1, one destination subrect, DMA buffer present, private data present, and zero patch-list slots. `callbacks.c:AdmissionDdiPresent` routes BLT to `AdmissionPresentBlt`; `present_windows.c` requires a non-null `pPatchLocationListOut` with at least two elements before encoding. In the same driver `callbacks.c:AdmissionDdiCreateContext` advertises `Caps.NoPatchingRequired=1`, `AllocationListSize=16`, `PatchLocationListSize=0` for virtual-addressed graphics contexts. These two contracts are incompatible for a BLT delivered to such a context. The first receipt does not name its process or prove its time relative to the live dump.

Pinned WDK26100 `d3dkmddi.h` `DXGKARG_PRESENT` marks `pPatchLocationListOut` and `PatchLocationListOutSize` **Not used** for the Win7+ union form and includes WDDM2 `DmaBufferGpuVirtualAddress`. `DXGK_ALLOCATIONLIST` exposes a WDDM2 union of `PhysicalAddress` and `VirtualAddress`; `SegmentId=0` means there is no physical prepatch information. The [Microsoft Residency Overview](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/residency-overview) explicitly says no patch list is allocated to a GPUVA `NoPatchingRequired` context and the small allocation list tracks written-primary synchronization. [DXGK_ALLOCATIONLIST](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/ns-d3dkmddi-_dxgk_allocationlist) documents the GPU virtual address member. Generic [DxgkDdiPresent](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/nc-d3dkmddi-dxgkddi_present) wording about filling patch lists describes the patching model; it cannot override the pinned newer no-patching contract. Classification FULL GRAPHICS; KMDOD/DISPLAY_ONLY admission and scheduler assumptions do not apply.

EXP890's 0x193 `VIDEO_DXGKRNL_LIVEDUMP` at boot+90.196 seconds has reason0x810 and only the capture worker stack `dxgkrnl!ProcessDeadlockThread` in a triage minidump. [Microsoft's 0x193 reference](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/bug-check-0x193--video-dxgkrnl-livedump) confirms it is not a real bugcheck; it does not define reason0x810 or name a KMD DDI. DWM's later C0000005 `dwmcore!CComposition::PreRender+2e4` at boot+142.489 seconds remains separate until a writer or causal chain is identified. EXP890 original ETL/registry evidence must be checked for ordering; without a timestamp for the first Present receipt, the live dump and rejection cannot be called one failure.

## Deterministic translation

WINDOWS CONTRACT: for a virtual-addressed full WDDM context, accept zero output patch slots. Source/destination are handles in the Present allocation list, and GPU virtual addresses are available in its WDDM2 union. `DxgkDdiPresent` must build an actual source-to-primary BLT or flip transaction, preserving command-buffer, fence, allocation ownership and primary synchronization. A successful status without an executed copy/flip is false.

AGX/ASAHI CONTRACT: Asahi's per-process UAT maps 16-KiB pages; m1n1 owns the already-latched DCP pool surface, DART and swap. The R168 KMD graph tracks the process's GPUVA-to-guest-IPA leaf mappings. Existing `AdmissionPresentBltExecute` does an ordered software BLT from a CPU-readable source to the local primary, but its Version1 command encodes segment physical locations and the physical submit/patch path. Source pages may be noncontiguous even when GPUVA is contiguous.

TRANSLATION: a patchless Present variant must validate the open source/destination handles and GPUVA ranges, encode stable GPU virtual source/destination addresses and the same rectangle geometry, and queue a versioned Present transaction on the virtual context. At execution, resolve every page through the owning process graph and CPU-visible backing, perform the actual copy with existing overlap/scratch semantics, signal the normal monitored fence, and retain the written-primary allocation reference required by WDDM. The physical Version1 path remains for contexts that advertise patching. Do not silently treat `DXGK_ALLOCATIONLIST.VirtualAddress` as a segment physical offset, remove only the patch check, or call success after dropping the copy.

WHAT IS STILL UNKNOWN: exact Windows allocation-list GPUVA values in the EXP890 failed BLT, the first rejection's UTC ordering versus the 0x193 live dump, and the writer of DWM's invalid pointer. These are evidence limits, not register/protocol guesses. A historical ETL pass may narrow timing; the triage dump alone cannot. No firmware/Mu/ACPI/capability change is indicated.

## Test and hardware gate

Focused original ETL pass: the complete UTC02:01:19–26 interval around the 0x193 debugger timestamp has51,776 events,708 DxgKrnl submit event178 records and zero `bPresent=true` records. The later WER write interval hit a100,000-event cap. A rejected Present can produce no submission, and its registry receipt has no UTC: there is no demonstrated direct correlation to the live dump. The dump does not identify a blocked KMD DDI. Stop equivalent ETL archaeology here.

The coherent implementation candidate is a Version2 patchless BLT command with allocation-list source/destination GPUVA, virtual submission, and pagewise graph resolution by the existing CPU Present worker. It must preserve the physical Version1 path, validate VA/guest IPA and ownership before writes, retain the render context through the queued fence and signal normal completion. This must be tested as an actual copy, not as a status-only acceptance.

WHAT REAL BUG OR INVARIANT WILL THIS TEST CATCH? A virtual render context advertises zero patch slots, but a valid source/destination BLT with one rectangle currently returns `STATUS_INVALID_PARAMETER` before producing a DMA transaction. RED must execute the real KMD Present route with zero patch slots and verify no copy is queued; GREEN must prove a versioned patchless GPUVA command, source/destination ownership and pagewise translation (including a noncontiguous 16-KiB backing), actual destination bytes, normal fence completion and unchanged Version1 physical BLT tests. Invalid/foreign/stale VA and exhausted DMA must fail closed with documented statuses. Avoid a manufactured test that only greps for a status literal.

The smallest future hardware discriminator is an exact package changing only the coherent GPUVA BLT path, after offline tests/WDK ARM64 build/sign/hash and supervisor review. Expected checkpoint: first BLT Present no longer fails solely for `PatchListSize=0`, an owned primary receives nonzero pixels, and 600+ seconds remain Code0/CPU8. If DWM still crashes, analyze its independent writer and 0x193 timing; do not add unrelated fixes to the same package. Recovery stays ordinary GPU-visible Code28 with exact-package cleanup only in verified hidden Code45 after host-verified original evidence; autologon stays.

## R169 implementation and verification checkpoint

The candidate changes only the Windows KMD/portable Present translation. Virtual contexts encode Version2 source/destination GPUVA from `DXGK_ALLOCATIONLIST.VirtualAddress`, emit no patch records, route `SubmitCommandVirtual` Present into the existing CPU packet queue, and retain the render context from queue admission through paging DPC. Queued preemption/reset releases that reservation; `DestroyContext` rechecks under the scheduler lock. At worker execution, the process graph is locked, source/destination ranges and access are checked, each 16-KiB GPUVA leaf is translated, source system IPA is read with `MmCopyMemory`, and writes are limited to the CPU-visible local view. The BLT takes a full source snapshot before destination writes. The physical Version1 path remains unchanged. No m1n1, Mu, ACPI, capability, DWM or 0x193 change is part of this candidate.

RED/GREEN evidence: real KMD Present returned `STATUS_INVALID_PARAMETER` on a virtual context with zero patch slots before R169 and now encodes Version2; virtual submit harness failed for missing route then queued the immutable transaction; CPU queue harness failed context retention then passed fence reservation/DPC retirement; queued preempt/reset reservation assertions failed then passed; scattered GPUVA helper failed as absent then copied two discontiguous source leaves. Extracted production G3 execution wrappers under ASan/UBSan copied 32,768 bytes from discontiguous system IPA to local primary and rejected an unmapped destination without writes. Focused suites are green; the full suite and WDK build are separate gates. The first full suite matched R168's aggregate 15F/38E baseline but exposed one new G4 replay-shim compile error, corrected with its focused replay green; rerun pending.
