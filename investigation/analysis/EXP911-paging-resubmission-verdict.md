# EXP911: Windows paging resubmission rejected before DWM discriminator

EXP911 tested receipt-only package 30.0.911.0 from source `26f5d890b25e38d620ef33bdf020d27527d60071`; KMD, UMD, probe, m1n1 and Mu behavior was unchanged from EXP910. The original boot `2026-10-01T12:52:32.5876710Z` reached Code0/Start12/CPU8/DWM1220 and the first probe at boot+69.037 s. It stopped at uptime 81.884 s. The host-preserved ARM64 kernel dump and exact EXP911 PDBs prove `0x119 VIDEO_SCHEDULER_INTERNAL_ERROR`, subtype `0x2`, NTSTATUS `C000000D`. The stack is `dxgmms2!VidSchiSubmitPagingCommand`, not a DWM Present or TDR reset worker.

The dumped `DXGKARG_SUBMITCOMMANDVIRTUAL` at `ffffaa84026e0a50` is a system paging context (`_ADMISSION_RENDER_CONTEXT.Object.Flags=5`, no Win32Transport), DMA VA `0x4101000`, 64 marker bytes and 480 private bytes (four 120-byte records), fence `0x1d3f`, flags `0x81` (`Paging|Resubmission`). The four records are virtual transfers from system segment 0 to local segment 2. The KMD scheduler snapshot has CompletedFence `0x1d3d`, LastSubmittedFence `0x1d3e`, no active/queued packet and idle preemption phase. This is a forward fence; the failure occurs in `AdmissionGpuvaG3SubmitVirtualPaging` before it calls the CPU queue because its input guard required flags exactly `0x01`. The documented Resubmission bit is permitted for a paging packet. `AdmissionDdiSubmitCommandVirtual` returns `C000000D` through this path; dxgmms2 then bugchecks. The precise Windows context scheduler and kernel dump identify this earlier lifecycle boundary. The active frame ring had one completed DWM submission 6441 and no branch7 result; EXP911 cannot test whether branch7 blocked the desktop.

Source-first ownership: WDK 26100 `DXGK_SUBMITCOMMANDFLAGS` and Microsoft [GPU Preemption](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/gpu-preemption) say a paging command preempted in the queue may be resubmitted with its original fence, whereas a nonpaging command gets a new fence. [SubmitCommandVirtual](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/nc-d3dkmddi-dxgkddi_submitcommandvirtual) permits `STATUS_INVALID_PARAMETER` for malformed input, but this flags81 input is well formed. The current KMD source is `gpuva_g3_windows.c::AdmissionGpuvaG3SubmitVirtualPaging`, `work_queue_windows.c::AdmissionCpuQueueSubmit`, `scheduler_windows.c::AdmissionDdiPreemptCommand`, and shared `apple_agx_scheduler.{h,c}`. Asahi AGX/UAT and m1n1 DCP/IRQ have no ownership of Windows scheduler fence IDs; Mu only exposes APPL0002 resources. No firmware, ACPI, power, render or display state is changed by the correction.

**ATOMIC CONTRACT:** Admit a valid paging `Resubmission` flag together with (1) KMD preservation of that bit when handing the packet to the CPU queue, (2) retention of the exact accepted queued fence IDs discarded by a successful boundary preemption, and (3) one-time requeue of a matching older paging fence after notification. These fields are invalid independently: accepting flags81 without the queue path still rejects a legitimate same-ID paging packet, while requeueing arbitrary old IDs violates monotonic completion. Ordinary submissions continue to use strict increasing fences. The queue rejects preemption-phase submission, an already completed fence, duplicate, foreign ID, and reversed order. Abort/reset clear replay eligibility. The bookkeeping uses an existing fixed queue bound; it makes no capability claim and never fabricates hardware completion.

**WHAT REAL BUG OR INVARIANT WILL THIS TEST CATCH?** The extracted production paging function and real scheduler reject EXP911's forward flags81 input before implementation, then admit the exact four-record packet with the original context and forward fence. A second RED after accepting flags81 proves that a queued paging fence still failed on same-ID replay; the corrected scheduler passes it once. The actual CPU queue, preemption callback and scheduler replay prove transfer and ordering. An abort regression was RED when replay eligibility survived a canceled preemption, then GREEN. Reserve bits and false replay remain rejected. ASan/UBSan and existing queue/scheduler tests pass. The full suite exact-ID comparison is recorded separately; host fixtures without Mesa/native dependencies retain their baseline failures.
