# C15 production legacy prepared-owner build hook

The legacy prepared compute route is default OFF. CPU1515 qualified the actual
PSO caller and matching NIR factory/destructor, with 116 nominal checks across
CS50/CS51 success and ordinary NULL callback cases. This hook supplies the eight
production objects to the real UMD without the private fixture wrappers.

WINDOWS CONTRACT: Release ARM64, native frontend and GPUVA only. Public DDI,
shader models and capabilities stay at the current legacy baseline. The normal
runtime verifier remains unchanged and authoritative for the complete committed
source manifest, runtime archive and compiled Resource.cpp projection.

AGX/ASAHI CONTRACT: the prepared compute owner consumes a separately owned NIR
clone. Shared metadata uses the qualified canonical shader_info.h. The source
and archive graph matches the qualified native1517 CPU build; eight production
units omit its two fixture objects and forced reference-observer include.

TRANSLATION: build-driver opts in explicitly, builds eight fresh objects under
reviewed profiles and a hash-bound request, checks their actual include closure,
then passes props and receipts to a mandatory MSBuild verification target.
Normal runtime plus five core archives remain in normal props; the hook adds
two extra core and nine checked translator archives, each bound to its actual
original archive receipt by JSON pointer. No unqualified historical runtime or
new source identity may be substituted into old receipts.

WHAT IS STILL UNKNOWN: native execution of this production build hook, actual
project evaluations and complete package linkage; actual GPU compilation and
execution through the enabled route. A new normal runtime qualification under
the final assembled source commit must precede these gates. CPU1515 does not
prove public DXIL/SM6 admission, physical owner initialization or full OOM policy.

Source review: actual1517 compile profiles and environment, actual production
UMD project/build-driver, unchanged verify-native-runtime-provenance.py and
build-asahi-runtime-closure.py. Core/source/archive initialization, runtime and
NIR ownership remain in their existing owning layers; this change owns build
provenance only. Firmware, KMD, recovery and advertised caps are unchanged.

WHAT REAL BUG OR INVARIANT WILL THIS TEST CATCH? A stale, absent or duplicate
object; a changed source or runtime Resource.cpp; a wrong snapshot, fixture
forced include, wrong COFF machine or changed archive must stop before linking.
Nine real-file tests exercise those deterministic cases, using minimal COFF test
DATA rather than claiming compiled semantics. All nine and five unchanged normal
runtime tests pass. Full host1630 tests retain exactly119 prior failures and no
new failures; log c502288f356756de51bb2036deb1558af989af1b6a58dc31eaa814a45fd0da39.
