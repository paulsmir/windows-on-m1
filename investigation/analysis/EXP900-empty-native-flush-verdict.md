# EXP900: empty-batch correction is not sufficient for DWM Present

The single behavior change in package `30.0.900.0` was R179: a generated native `agx_flush_batch` with no draws, CDM work, or initialized/clear VDM work aborts/resets without poisoning `agx_context.any_faults`. This matches the pinned upstream Asahi no-work reset contract. An extracted actual-body ASan/UBSan test was RED before the change and GREEN afterward; it also proves active work and failed abort stay fail-closed. No KMD, DXGI table/caps, firmware, Mu, or scanout behavior was changed.

Original boot `2026-09-30T16:03:56.8914970Z` reached Code0/Start12/status0/CPU8 and stayed alive beyond 781.777 seconds without an observed kernel stop. The live DWM PID1236 still entered native `_Present` with `any_faults=1`, backend failed=0, batch=0, draws=0 **before** `AgxWin32AsahiContextFlushForPresent`; the call returned `E_FAIL`, and neither `FlushStatus` nor `pfnPresentCb` ran. Thus the R179 deterministic fix did not remove DWM's first context fault. The current DCP swap11 sequence3 IOVA `0x102a0000` matched +120/+300/+600 after latch, each 4,096,000-pixel snapshot still zero (`cache_clean=0`). R179 is **rejected as sufficient for DWM/scanout**, not reverted as a software invariant fix.

DWM1236 later faulted and was replaced by PID10188. The original WER dump SHA `8f7d87508fc4afb08d93b8465fbf5d023467cb27936f6e0187c19c208afa0895` was preserved; CDB found C0000005 reading `0x92f9c90` at `d2d1!CDImageContext::Initialize+0x338` while uDWM created a border visual. The exception stack does not contain AppleAgx, and this does not identify the writer or link the crash to the pre-Present fault. Treat it separately.

The capped original ETL session was absent when the packaged collector tried to stop it. A complete periodic original snapshot and original guest ETL matched SHA `f6dc20468ed80272daf64318651537fcdfc53f7e8b23d5d83ed0700cc25ac5a6`; a no-extra-space hardlink and receipt were created under Code0 before reset. Twelve original files including the WER dump were independently host size/SHA verified. Ordered restart stalled after System1074; only owning `run_uefi` was terminated after the original host gate. Immutable hidden boot reached Code45/exact oem5/serviceStopped/armnull. Hidden AutoLogger reused the guest ETL hardlink, so that changed guest file is not original evidence. A 4,819-byte exact-state/events inventory was independently host size/SHA verified. Final manifest `.local/experiments/EXP900-probe-symbols/final-host-manifest.json` SHA `523196aeaff12c40918210adf44c4c8ea14aee3f5cb6a801ebacec9e5c295d22` ties original 12/12 and hidden 1/1 gates before exact Code45 diagnostic/package cleanup. Ordinary GPU-visible recovery was durable at `16:41:34Z`: one APPL0002 Code28, package/service/module/signer/arm/diagnostics absent, CPU8, both disks OK, USB5, RDP running, autologon1. No package was removed from live Code0.

The next causal target is the **first setter** of `agx_context.any_faults` before DWM Present. Exact generated native sources have multiple possible setters in `agx_batch.c`, `agx_pipe.c`, and `agx_state.c`; the EXP900 comparison does not rank one strongly enough for another behavior patch. Use one bounded first-transition per-context site receipt, retaining the R177/R178 Present receipts and unchanged driver behavior, then reproduce the observed owning defect offline RED→GREEN before any behavior-only hardware verification. Do not change NO_REDIRECTION, register an unnegotiated Present1 slot, or attribute the DWM crash to AppleAgx without writer evidence.
