# EXP896 live-DWM DDI measurement verdict

EXP896 **ran but did not measure the intended DDI counters**. The original Code0/CPU8 boot lasted to the last healthy sample at +154.518 s, then reset before the +300/+600 scanout checkpoints. The +120 read-only D3DKMTEscape returned `STATUS_NOT_SUPPORTED` on both enumerated adapters. Package896 was built with `-GpuvaG3Qualification`; the new counter state, callback writes and query were guarded by `APPLE_AGX_SUBMIT_QUALIFICATION` only, so no counter code was in the shipped KMD. The offline gate regression failed before correction and passes after commit `d58b5655fd04c6ae88b8d141a9d248f6378e2d83`. That correction has **not** been built or hardware-validated.

## Reproducible original evidence

- Two original periodic snapshots (three files each) have independent host size/SHA verification, receipts `63ad45425d63f648c3e8f99383998d57ed85040000928abb39d8721bae97e7eb` and `29dc8223bf926f9f0a14708f8498ddfc94998e1fd78a6f7b9e77df9c1f5f6aa5`.
- Hidden Code45 dump plus five other files total 959,771,667 bytes were independently host size/SHA verified, aggregate manifest `5d8b5aababc5e391b3ba35e62ed6d203986c2001b01b4c97b06303daf28db4ac`, **before** exact package/diagnostic cleanup. `MEMORY.DMP` SHA `8c544f7e20001a6a8666ec30f2fdcc09c0866ab92cc145768db385879d70f0a3`; matching minidump SHA `ae79dcca6e7d864f64663f326c923603cf4f825c38f61c9350513dbce85ab573`. [Microsoft's bugcheck table](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/bug-check-0x119---video-scheduler-internal-error) labels subtype D invalid DMA page-fault parameters. Do **not** claim that a specific PageFaultFlags bit was set; the dump shows a scheduler rejection at this notification boundary, and the precise dxgmms2 rule needs a separate source/trace derivation.

## Present transaction found in the dump

The stopped paging worker's `PresentCopyCommand` is a valid Version2 GPUVA BLT, 184 bytes, one full-surface rectangle (2560×1600), source GPUVA `0x1050000`, destination GPUVA `0xB0000`, both descriptions `0xFA0000` bytes. This proves **a full-primary BLT Present transaction reached the virtual paging-copy worker**; the compiled-out DDI probe means the initiating user process cannot be attributed specifically to DWM from this receipt alone. DWM's WER dump SHA `d52e5d0e8fc0ac6164a9c8272be64adadb08381aecfe7a823e66436826ef0c5d` is retained separately; temporal proximity does not prove a common writer.

The context's G3 root `0x9D6130000` matched the process graph root, neither context nor process was poisoned, and `Graph.Uncertain=0`. The graph root/table parent edges were present. Reconstructing the graph's 16 KiB leaf list in the full dump showed the destination's 1,000 pages mapped and writable, but only 158 of the source's 1,000 pages published. The **first source gap is GPUVA `0x1054000`**, one page after its base. `AdmissionGpuvaG3ExecutePresentVirtual` requires full source and destination `GraphContainsRangeAccess`; it returned `STATUS_INVALID_ADDRESS (0xC0000141)` with zero bytes copied. The paging notification at fence `0x6C54` reported that failure via `DXGK_INTERRUPT_DMA_FAULTED`, immediately preceding the 0x119/D stop. This explains why no nonzero primary reached the DCP in this transaction without guessing about cache visibility.

The current `AdmissionPresentBlt` implementation also substitutes a full-screen rectangle whenever both allocation descriptions are 2560×1600, regardless of the caller's source/destination rectangles. The dump proves the **encoded** rectangle is full-screen, not what dxgkrnl originally requested; whether this override caused the sparse-source failure remains a hypothesis. Do not remove the override as a hardware fix without the original Present arguments or a deterministic documented contract test.

## Causal decision and recovery

**Owning boundaries:** Windows dxgkrnl/VidMM owns Present ordering and residency; KMD owns truthful Present encoding, G3 graph translation, queued copy admission and legal interrupt completion; m1n1 owns DCP swap/latch; Mu's reserve/ACPI and AGX power/IRQ firmware are unchanged. Microsoft [interrupt notification documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmddi/ns-d3dkmddi-_dxgkargcb_notify_interrupt_data) distinguishes DMA-fault status from page-fault flags; neither a broker refusal nor an unmapped software Present may be acknowledged as successful scanout.

The next offline discriminator is to reconstruct why VidMM's source allocation is sparse at this full-primary BLT: compare the original Present rectangle and returned allocation residency with the graph's PTE map/unmap lifetime; test the smallest truthful BLT/residency translation and failure-completion contract. The G3 diagnostic-gate correction may be packaged as a **measurement-only** run, but it must not be combined with an independent paging/presentation behavior fix in one hardware experiment. Do not blindly rerun package896: its query is compiled out and it stopped at ~180 s. If a corrected measurement is run, capture original source/destination rectangles, exact process/context, per-DDI counts and graph walk-failure reason before the observed stop boundary, then matched late DCP snapshots only if the original boot survives.

Recovery: hidden Code45/exact oem5 evidence gate passed, only exact package and diagnostics were removed, and ordinary immutable GPU-visible Code28/one APPL0002/package0/CPU8/disks2OK/USB5/RDP/autologon1 was durable at `2026-09-30T10:31:44Z`. Only byte-verified guest duplicate memory and DWM dumps were removed afterward under Code28/package0, restoring C: free space to 970,883,072 bytes; host evidence/PDBs and guest minidump remain. No package from a live Code0 guest was removed.
