# EXP807 — read-only scanout content discriminator

WHY THIS HYPOTHESIS: (1) EXP805 reached CDD BltToPrimary/Present and DCP latch but the lit panel was black. (2) EXP806 displayed opaque BGRA stripes written by m1n1 at the validated primary PA and presented through the same DART IOVA. (3) R90's photo shows possible Windows texture in two stripes, but neither producer bytes nor cache visibility was measured.

Sources inspected: `GPU_CURRENT_STATE.md` top boundary; EXP805/806 ledger entries; R90 in `.local/tandem/REVIEW.md`; KMD `scanout_windows.c`, `display.c` and source-address receipt; m1n1 `hv_agx_scanout_broker.c`, `hv_agx_scanout_service.c`, `hv_agx_power_mmio.c`, `display.c`. The relevant Windows CDD Blt and PresentDisplayOnly events are ETL observations, not Apple KMD callback implementations.

Contract: KMD owns the selected primary allocation and queues its segment offset; m1n1 validates IPA→PA, maps the pool in both DARTs and submits PA-derived IOVA to DCP. Windows CDD owns CPU writes; the existing Apple KMD path performs no explicit cache clean before queueing. EXP807 adds a read-only pre-swap m1n1 snapshot of the selected surface: nonzero pixel count, BGRA channel averages, FNV-1a hash, corners, sequence, PA and IOVA. KMD's source receipt records the allocation handle, segment address, selected CPU/PA/IPA/offset and absence of explicit clean. Per-call source-address trace and ETL correlate later frames; the first durable receipt does not prove CDD's write destination.

Format gate: `D3DDDIFMT_A8R8G8B8` value 21 has BGRA byte order on little-endian ARM64. m1n1 uses `FMT_BGRA`, colorspace 2, SDR gamma; EXP806's opaque `0xffffffff` white sample was correct in host memory. Pink panel appearance alone does not justify a format change.

Smallest checkpoint: exact diagnostic package and m1n1 image, frozen Mu and recovery, one cold full-owner launch. Require snapshot before every requested swap, A408/D589 latch, pinned SSH/Code0 and operator LOOK_NOW/LOOK_DONE observation. If the selected PA is nearly all zero after CDD activity, investigate CDD shadow→primary copy/selection. If nonzero, distinguish cache visibility and timing with one next experiment; nonzero alone does not identify which. Any failed identity/arm/SSH gate returns to the GPU-hidden dump-first recovery, otherwise exact-package cleanup then ordinary Code28. Record before/after in `EXPERIMENTS.md` and hashes before installation.
